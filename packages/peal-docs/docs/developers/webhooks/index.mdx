A webhook is a request Peal sends to an address of yours when something happens in a workspace: a post went out or failed, a channel needs reconnecting, a file is ready. Your product or automation hears about it at once, so it doesn't have to keep asking the [API](/developers).

Peal signs every request the way the [Standard Webhooks](https://www.standardwebhooks.com) specification says ([its text](https://github.com/standard-webhooks/standard-webhooks/blob/main/spec/standard-webhooks.md)). The libraries written for that specification verify Peal's deliveries as they are.

## Who manages them [#access]

You can manage webhooks from four places:

| Where            | How                                                                                                                                                                                                                                                 |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The web app      | **Settings**, then **Webhooks**                                                                                                                                                                                                                     |
| The API          | The `webhooks` group, [below](#api)                                                                                                                                                                                                                 |
| The command line | `peal webhooks` ([command line](/developers/cli))                                                                                                                                                                                                   |
| MCP              | The [MCP](/developers/mcp) tools `list_webhooks` and `list_webhook_deliveries`, which read; `create_webhook` and `update_webhook`, which add and change an endpoint; `send_test_webhook` and `redeliver_webhooks`, which make Peal call your server |

Two permissions cover them:

| Permission       | What it allows                                                              | Who holds it      |
| ---------------- | --------------------------------------------------------------------------- | ----------------- |
| `webhook:read`   | List the endpoints and read their deliveries                                | Owners and admins |
| `webhook:manage` | Add, change, turn off and delete endpoints, rotate secrets, send and resend | Owners and admins |

An API key does what its permissions allow, and an OAuth client what you let it do. A client that's only allowed to read lists endpoints and deliveries, and changes nothing. Staff acting as a member can't change a workspace's webhooks.

Every plan includes webhooks, and so does an instance that doesn't bill.

## Endpoints [#endpoints]

An endpoint is an address, the events it wants, a description and whether it's on. You can also limit it to some channels and workspaces. A workspace has 10 endpoints at most, whatever its plan.

Each endpoint has these settings:

| Setting                                | Rules                                                                                                                                                                                                                                                                                                                |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Address                                | An HTTPS URL on the default port (443), on a public host, without a user name or a password, 2048 characters at most.                                                                                                                                                                                                |
| Events                                 | The [event types](/developers/webhooks/events#events) the endpoint subscribes to, at least one. It's sent those and nothing else.                                                                                                                                                                                    |
| Description                            | What the endpoint is for, up to 200 characters.                                                                                                                                                                                                                                                                      |
| On or off                              | While an endpoint is off, Peal sends it nothing and its pending deliveries fail. What happens in the meantime isn't kept for it, so turning it back on doesn't replay anything.                                                                                                                                      |
| Scope, over the API                    | `workspace`, the default, hears this workspace. `partner` hears every workspace a [partner account](/developers/embedding/operate#webhooks) owns too, and is only allowed on the account's home workspace; elsewhere it answers 404 `PartnerNotFound`. You set it when you create the endpoint, and it can't change. |
| Only these channels (`channelIds`)     | 50 at most. No list means every channel ([Filters](#filters)).                                                                                                                                                                                                                                                       |
| Only these workspaces (`workspaceIds`) | 200 at most, on a `partner` endpoint only. No list means every workspace it hears ([Filters](#filters)).                                                                                                                                                                                                             |

<Callout type="warning" title="The address must stay public">
  Peal checks that the host resolves to public addresses when you save it, and
  again before every request. An address that later points inside a private
  network is sent nothing. Peal follows no redirect either, so an answer in the
  300s is a failure. Give the final address.
</Callout>

### Filters [#filters]

With `channelIds`, the endpoint only receives events about those channels. Which events pass depends on what they're about:

| The event is about | Events                                                                                                                     | Sent when                                                                                        |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| One channel        | `post.published`, `post.failed`, `post.unconfirmed`, `post.unpublished`, `post.unpublish_failed`, `channel.*`, `comment.*` | Its channel is listed                                                                            |
| A whole post       | `post.scheduled`, `post.unscheduled`, `post.cancelled`, the approval events                                                | One of the post's channels is listed. The payload is unchanged.                                  |
| No channel         | `media.*`, `boost.*`                                                                                                       | Always, whatever the endpoint lists. Leave those types out of its events if you don't want them. |

With `workspaceIds`, a `partner` endpoint only hears those workspaces, and its home workspace only if it's listed. An endpoint with the `workspace` scope refuses the field (`WebhookFilterRefused`, or `InvalidRequest` when you create it).

Filters apply when each event happens, with the endpoint as it is at that moment. [Sending a delivery again](/developers/webhooks/delivery#log) sends it to its endpoint whatever the filters say now.

Peal only checks the shape of the ids in a filter, so an id that names nothing matches nothing. A filter stays as you saved it when a channel is disconnected or a workspace leaves the partner account. The endpoint's form lists such a channel apart, ticked, as **A channel no longer connected**. Untick it to take it off.

### Headers of your own [#headers]

An endpoint can carry up to 5 headers of your choice, sent with every delivery next to Peal's own. A gateway in front of your server might ask for a token, for example, or you might route on a header. They're static: the same on every delivery and every attempt.

Names and values follow these rules:

- A name is an HTTP token (letters, digits and ``!#$%&'*+.^_`|~-``), 64 characters at most, and once per endpoint whatever its case. `Authorization` is allowed.
- A value is visible ASCII on one line, 1,024 characters at most. It can hold spaces, but not at either end.

Peal refuses the names it sets itself, and those that describe the body, change how the request is delivered or change how its answer is encoded: any name starting with `webhook-` or `Content-`, `Host`, `User-Agent`, `Cookie`, `Connection`, `Keep-Alive`, `Proxy-Connection`, `TE`, `Trailer`, `Transfer-Encoding`, `Upgrade`, `Expect` and `Accept-Encoding`. None of yours ever replaces one of Peal's.

#### Change the headers [#headers-change]

Values are write-only. Peal stores them encrypted, as it does the secret, and never shows them again. The endpoint lists their names (`headerNames`), and Peal never writes the values in its logs or in the delivery log. To change them, send the endpoint's whole list in `headers`:

| In `headers`                 | Result                                                                                          |
| ---------------------------- | ----------------------------------------------------------------------------------------------- |
| A header with its `value`    | Sets it                                                                                         |
| A header by its `name` alone | Keeps the value the endpoint has under that name (422 `WebhookHeadersRefused` when it has none) |
| A header left out            | Removes it                                                                                      |
| `[]`                         | Removes them all                                                                                |
| No `headers` field           | Keeps them                                                                                      |

Values stay with their origin. Peal only sends a value to the origin (scheme, host and port) of the address it came with, and keeps it sealed to that origin. Changing `url` to another path on the same host keeps the values.

Moving to another host needs `headers` in the same request, with every header's `value`, or `[]` to remove them. Otherwise the request answers 422 `WebhookHeaderValuesRequired` and nothing is saved. Whoever moves the endpoint must know the values again, so the address alone never carries them somewhere else.

<Callout type="warning" title="Headers aren't signed">
  The [signature](/developers/webhooks/requests#verify) covers the event's id,
  timestamp and body, as the specification says. Verify it whatever headers you
  receive.
</Callout>

## Through the API [#api]

The `webhooks` group has these endpoints:

| Endpoint                                                                                     | What it does                                                                                        |
| -------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `GET /api/workspaces/{workspaceId}/webhooks`                                                 | Lists the endpoints, oldest first                                                                   |
| `POST /api/workspaces/{workspaceId}/webhooks`                                                | Adds an endpoint, and answers its `secret` once                                                     |
| `GET /api/workspaces/{workspaceId}/webhooks/{endpointId}`                                    | Shows one                                                                                           |
| `PATCH /api/workspaces/{workspaceId}/webhooks/{endpointId}`                                  | Changes its address, description, events, filters or headers, or turns it on or off                 |
| `DELETE /api/workspaces/{workspaceId}/webhooks/{endpointId}`                                 | Deletes it, with its secret and its log                                                             |
| `POST /api/workspaces/{workspaceId}/webhooks/{endpointId}/secret`                            | Rotates its secret, and answers the new one once                                                    |
| `POST /api/workspaces/{workspaceId}/webhooks/{endpointId}/test`                              | Sends it a test event, or a sample of `eventType`                                                   |
| `GET /api/workspaces/{workspaceId}/webhooks/{endpointId}/deliveries`                         | Lists its deliveries, newest first, 30 a page, by `status` and `eventType`                          |
| `POST /api/workspaces/{workspaceId}/webhooks/{endpointId}/deliveries/{deliveryId}/redeliver` | Sends a delivery's event again                                                                      |
| `GET /api/workspaces/{workspaceId}/webhooks/deliveries`                                      | Lists the deliveries of every endpoint, by `status`, `endpointId`, `eventType`, `since` and `until` |
| `POST /api/workspaces/{workspaceId}/webhooks/deliveries/redeliver`                           | Sends many deliveries again: `deliveryIds`, or `endpointId` with `since`, `until` and `eventType`   |

The `GET` requests need `webhook:read`. Everything else needs `webhook:manage`.

### Add an endpoint [#create]

This endpoint hears when posts go out, fail or stay unconfirmed, and sends a token for the gateway in front of your server:

<CodeGroup>

```ts Node.js
import { PealClient } from "peal-sdk";

const peal = new PealClient({ token: process.env.PEAL_API_KEY });
const workspaceId = process.env.PEAL_WORKSPACE_ID ?? "";

const { endpoint, secret } = await peal.webhooks.create({
  workspaceId,
  url: "https://hooks.example.com/peal",
  description: "Order system",
  eventTypes: ["post.published", "post.failed", "post.unconfirmed"],
  headers: [{ name: "Authorization", value: "Bearer <your gateway token>" }],
});
```

```python Python

    event_types=["post.published", "post.failed", "post.unconfirmed"],
    headers=[WebhookHeader(name="Authorization", value="Bearer <your gateway token>")],

```

### Errors [#errors]

Errors come in the API's format, each with a `code` in snake case next to its name, such as `webhook_url_refused` for `WebhookUrlRefused` ([Errors](/developers/conventions/errors#errors)). An API key's requests count towards its [rate limit](/developers/conventions/rate-limits#rate-limits). The `webhooks` group answers these errors of its own:

| Status | Error                         | When                                                                                                       |
| ------ | ----------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 404    | `WebhookEndpointNotFound`     | The workspace has no endpoint with this id.                                                                |
| 404    | `WebhookDeliveryNotFound`     | The endpoint has no delivery with this id, or its log no longer keeps it.                                  |
| 409    | `TooManyWebhookEndpoints`     | The workspace already has 10 endpoints.                                                                    |
| 409    | `WebhookEndpointDisabled`     | You asked for a test or a resend on an endpoint that's off.                                                |
| 422    | `WebhookFilterRefused`        | `workspaceIds` on an endpoint with the `workspace` scope. `field` names it.                                |
| 422    | `WebhookHeadersRefused`       | A header sent without a `value` that the endpoint doesn't have.                                            |
| 422    | `WebhookHeaderValuesRequired` | A new `url` on another origin, on an endpoint with headers, without every header's `value` or `[]`.        |
| 422    | `WebhookUrlRefused`           | Peal doesn't deliver to the address. `reason` says why, below.                                             |
| 429    | `TooManyWebhookSends`         | The hour's test events and resends are used up. See [the delivery log](/developers/webhooks/delivery#log). |
| 503    | `WebhooksNotConfigured`       | The instance can't keep a signing secret. See [Self-hosting](#self-hosting).                               |

`WebhookUrlRefused` gives one of these reasons:

| `reason`      | The address                                                       |
| ------------- | ----------------------------------------------------------------- |
| `malformed`   | isn't a URL.                                                      |
| `notHttps`    | isn't HTTPS, or names a port other than 443.                      |
| `credentials` | carries a user name or a password.                                |
| `tooLong`     | is longer than 2048 characters.                                   |
| `notPublic`   | has a host that is, or resolves to, an address that isn't public. |
| `unknownHost` | has a host name that doesn't resolve.                             |
| `ownServer`   | is the Peal server's own address, where Peal never delivers.      |

The [API reference](/reference) lists each endpoint's parameters and answers.

## Self-hosting [#self-hosting]

Webhooks need no setting of their own. Signing secrets are encrypted with the keys in [`PEAL_TOKEN_KEYS`](/self-hosting/environment-variables#channels), like the tokens of connected channels. Without it, the instance still starts, but adding an endpoint or rotating a secret answers 503 `WebhooksNotConfigured`.

Deliveries leave from the server, so it must be able to reach your receivers over HTTPS. They only go to public addresses: an endpoint on `localhost` or inside your private network is refused, on your own instance too.
