You can find the posts that failed last week, everything still scheduled on one channel, or the posts a key created. The samples build the client as [Posting through the API](/developers/posting#start) explains.

## Filter the posts [#search]

`GET …/posts/search` lists the workspace's posts, whatever their state, a page at a time. A page holds 20 posts unless `limit` says otherwise, and 100 at most. When you give several filters, a post must match all of them. The [MCP tool](/developers/mcp/tools#tools) `list_posts` takes the same filters, and `peal posts list` lists the same posts ([Command line](/developers/cli/posts#posts)).

The request takes these parameters:

| Parameter     | What it keeps                                                                                                                                                   |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `status`      | `draft`, `awaitingApproval` (waiting for an [approval](/guides/posts/review), with its time kept), `scheduled`, `publishing`, `finished` or `cancelled`         |
| `outcome`     | How a finished post ended: `published`, `partiallyPublished`, `unconfirmed`, `failed` or `cancelled`                                                            |
| `channelId`   | Posts with a target on that channel                                                                                                                             |
| `platform`    | Posts with a target on a connected channel of that platform                                                                                                     |
| `tagId`       | Posts filed under that tag                                                                                                                                      |
| `queueId`     | Posts that queue placed ([Queues](/developers/posting/queues#queues))                                                                                           |
| `recyclingId` | Posts that recycling rule made ([Repeat a post](/developers/posting/queues#recycling))                                                                          |
| `removed`     | `true`: posts Peal deleted from at least one channel's platform; `false`: posts deleted from none ([Unpublish a post](/developers/posting/published#unpublish)) |
| `from`, `to`  | Posts scheduled from `from` (included) to `to` (excluded). Either one leaves out posts without a time.                                                          |
| `createdVia`  | `web`, `apiKey` or `application`                                                                                                                                |
| `authorId`    | Posts that user created                                                                                                                                         |
| `sort`        | `createdDesc` (the default) or `createdAsc`, by creation; `scheduledDesc` or `scheduledAsc`, by scheduled instant, which list only posts with a time            |
| `limit`       | How many posts a page holds, from 1 to 100                                                                                                                      |
| `cursor`      | The `nextCursor` of the previous page                                                                                                                           |

This request lists the failed Bluesky posts, the latest scheduled first:

```ts Node.js
import { PealClient } from "peal-sdk";

const peal = new PealClient({ token: process.env.PEAL_API_KEY });

const page = await peal.posts.search({
  status: "finished",
  outcome: "failed",
  platform: "bluesky",
  sort: "scheduledDesc",
  limit: "50",
});
```

Each post comes whole, with its targets, their status, address and failure reason. `channels` gives the platform of each channel on the page that's still connected, so you can label each target without another request.

## Read the next page [#next-page]

Pass `nextCursor` as `cursor`, with the same filters and sort. It's null on the last page.

A cursor marks where its page ended, so posts created, moved or deleted in the meantime never make a page repeat a post or skip one. A cursor from another sort, or one no page returned, answers 400.

<Callout type="info" title="A calendar can read a whole range in one request">
  `GET …/posts?from=…&to=…` is still available. It lists the posts scheduled
  between two instants, at most 62 days apart, by scheduled instant, in one
  answer. Drafts aren't included.
</Callout>
