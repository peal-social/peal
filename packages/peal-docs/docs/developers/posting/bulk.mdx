You can send up to 50 posts in one request, or import up to 100 from a CSV file, through the API, the SDKs or the command line. The samples build the client as [Posting through the API](/developers/posting#start) explains.

## Send several posts in one request [#bulk]

`POST …/posts/bulk` creates and sends up to 50 posts, each as `create` would. Each item is one post, with its own channels, content, options and time. So the same content at two times is two items, and so is a post that goes out at a different time on each channel.

Peal takes the items in order, one at a time, and each stands on its own. A refused item doesn't stop the others from being made, and nothing is undone.

The answer is 200 as long as Peal could read the request, even if it refused every item. `items` gives one result per item, by its place in the request (`index`, from 0):

- `created`, with its post.
- `refused`, with what `create` would have answered for that item alone, as data: its content's violations, unknown channels or media, a time that has passed, the plan's limit or a duplicate.

A request Peal can't read at all (malformed, with no item, or with more than 50) answers 400 and makes nothing.

The plan's limits hold across the whole request. Once the month has no room left, the remaining items are refused. Each item is also checked for the same content on the same channel against the posts made before it, the request's earlier items included ([Duplicate posts](/developers/posting#duplicates)).

### Send it again safely [#bulk-idempotency]

An `Idempotency-Key` header makes the whole request safe to send again within 24 hours. Peal keeps each item under the key and its place:

- The same request sent again answers the posts it made, with `replayed` true. It also makes the items that weren't made the first time, if they can be now.
- An item that changed under the same key is refused with `IdempotencyKeyReused`.
- An item can carry its own `idempotencyKey`, which then replaces the header's for that item.

## Import posts from a CSV file [#import]

`POST …/posts/import` creates and sends the posts a CSV file lists, one per row. In the web app, [Import from a file](/guides/posts/drafts#import-screen) checks a file and imports it through this endpoint.

The file's first line names the columns, in any order:

| Column            | Required | What it holds                                                                                                                                             |
| ----------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `text`            | yes      | The post's text                                                                                                                                           |
| `channels`        | yes      | Channel ids, separated by spaces, commas or semicolons                                                                                                    |
| `at`              | yes      | `now`; an instant with its offset, such as `2026-11-20T09:00:00Z`; or a local time without one, such as `2026-11-20 10:00`, read in the row's `time_zone` |
| `time_zone`       | no       | An IANA zone, such as `Europe/Paris`. UTC if left out.                                                                                                    |
| `media`           | no       | Ids of ready media of the workspace                                                                                                                       |
| `allow_duplicate` | no       | `true` or `false` ([Duplicate posts](/developers/posting#duplicates))                                                                                     |
| `idempotency_key` | no       | The row's own idempotency key                                                                                                                             |

A row is a single post, with one text for all its channels. A [thread](/guides/posts#threads), a different text on one channel or a platform's options don't fit in a cell, so send those through `create` or `bulk`. A file that names any other column is refused whole.

### Write the file [#csv]

Cells follow RFC 4180 strictly, so a text is never cut short. A cell that holds a comma, a quote or a line break goes between double quotes, and a quote inside it is doubled. A row ends after its last cell, with no trailing comma. A file holds at most 100 rows under its first line, and 1,000,000 characters.

```csv title="posts.csv"
text,channels,at,time_zone,media
Our spring catalogue is out.,0190f3a0-0000-7000-8000-00000000c001 0190f3a0-0000-7000-8000-00000000c002,2026-11-20 10:00,Europe/Paris,0190f3a0-0000-7000-8000-00000000a001
"Last days: the ""spring"" prices end on Sunday, at midnight.",0190f3a0-0000-7000-8000-00000000c001,2026-11-27T09:00:00Z,,
```

```json
{
  "created": 0,
  "dryRun": true,
  "rows": [
    { "_tag": "valid", "row": 1 },
    { "_tag": "valid", "row": 2 }
  ]
}
```

Peal checks every row first, the way `validate` checks a post, and then checks the file as a whole:

- A row an earlier row leaves no room for in its month is refused with `PlanLimitReached`.
- A row that repeats an earlier row on the same channel, less than 23 hours from it, is refused with `DuplicatePost`. Its `message` names that row, since there's no post to name yet.
- A row that reuses an earlier row's `idempotency_key` with a different post is refused with `IdempotencyKeyReused`.

<Callout type="info" title="One invalid row stops the whole import">
  Peal makes nothing unless every row is valid. `dryRun: true` stops there even
  when they all are. Otherwise Peal then makes the rows in order, as `bulk`
  makes its items.
</Callout>

### Read the result [#import-result]

`rows` holds one result per row, by its place under the first line, from 1. Blank lines aren't rows, and aren't counted. Each result has one of these tags:

| `_tag`       | Meaning                                                                                                                                                                                                                                                                                                                |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `created`    | The row's post was made. `post` holds it, and `replayed` says whether its idempotency key answered a post made before.                                                                                                                                                                                                 |
| `valid`      | The row was checked and not made, either in a dry run or because another row kept the file from being imported.                                                                                                                                                                                                        |
| `refused`    | `refusal` holds what `create` would have answered for it. A row that passed the check is also refused when something changed since, or when it repeats an earlier row.                                                                                                                                                 |
| `unreadable` | `problems` names the cells at fault: each `column`, `missing` when the row needs it, or `invalid` for what it holds. A row with more or fewer cells than the first line names isn't read at all, and `cells` says how many were `expected` and `found`. A comma in a text that isn't between double quotes causes one. |

```json
{
  "created": 0,
  "dryRun": false,
  "rows": [
    { "_tag": "valid", "row": 1 },
    {
      "_tag": "unreadable",
      "row": 2,
      "problems": [{ "column": "at", "problem": "invalid" }]
    }
  ]
}
```

The answer is 200 once Peal could read the file. A file it can't read at all answers 422 `ImportUnreadable`, and nothing is made. `problem` says why, and `column` names the column when the problem is about one:

| `problem`           | The file                                                                                  |
| ------------------- | ----------------------------------------------------------------------------------------- |
| `empty`             | is empty                                                                                  |
| `unterminatedQuote` | has a quoted cell that never ends                                                         |
| `strayQuote`        | has a double quote inside a cell that isn't between quotes, or text after a closing quote |
| `unknownColumn`     | names a column Peal doesn't know                                                          |
| `repeatedColumn`    | names the same column twice                                                               |
| `missingColumn`     | lacks a column it needs                                                                   |
| `tooManyRows`       | has more rows than one import takes                                                       |

```json
{ "_tag": "ImportUnreadable", "problem": "missingColumn", "column": "at" }
```

An `Idempotency-Key` header works as it does on `bulk`, row by row.
