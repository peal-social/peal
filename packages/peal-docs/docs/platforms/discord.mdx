You connect a Discord channel with a webhook made in its settings. There's no app to add and no account to sign in with, and Peal posts under the webhook's name.

## At a glance [#at-a-glance]

Here's what a Discord post can hold:

|                     |                                     |
| ------------------- | ----------------------------------- |
| Text                | {{platform-discord-text-en}}        |
| Images and videos   | {{platform-discord-media-en}}       |
| Their size together | {{platform-discord-media-total-en}} |
| Parts               | {{platform-discord-parts-en}}       |
| Alt text            | {{platform-discord-alt-en}}         |

What each file type must be is in [Images and videos](/guides/media#platforms). Each Discord channel counts as one account on your [plan](/guides/workspace/billing).

## Connect a channel [#connect]

<Steps>
  <Step title="Make a webhook">
    In Discord, open the channel's settings, go to **Integrations**, then
    **Webhooks**, and make a webhook for Peal. Its name is what the channel
    shows as the author of Peal's posts. Click **Copy Webhook URL**.
  </Step>
  <Step title="Paste it in Peal">
    On **Channels**, under **Discord**, paste the address into **Webhook
    address** and click **Connect Discord**. Peal reads the webhook on Discord
    and keeps its address encrypted, so you won't see it again.
  </Step>
</Steps>

Peal checks the address before it calls anything. It takes one that starts with `https://discord.com/api/webhooks/` or the older `https://discordapp.com/api/webhooks/`, from Discord's test builds too (`canary.discord.com`, `ptb.discord.com`). It refuses any other address, and it always calls Discord's own API.

Only an incoming webhook, the kind a channel's settings make, can post messages.

### When the webhook changes [#webhook]

Here's what happens when the webhook changes:

- If you connect another webhook of the same channel, Peal reconnects that channel with the new address.
- If your server moved the webhook to another channel, connecting it reconnects its channel too, which now posts there. It doesn't count as a second channel on your plan.
- If you delete the webhook in the channel's settings, Peal marks the channel to reconnect and stops calling it. That's how you cut Peal off.

## What a post becomes [#posts]

Peal sends the text as you type it, and Discord reads it as its own markdown: `**bold**`, `> quote`, a link. Peal changes nothing in it.

Mentions don't notify anyone unless you turn on **Notify the people and roles it mentions**. Until then, `@everyone`, a role or a person typed in the text shows in the message, and nobody gets pinged.

The parts of a [thread](/guides/posts#threads) go out as messages one after another in the channel.

In a forum or media channel, the first part opens a forum post titled with **Forum post title**, and the later parts go inside it. Without a title, Discord refuses the post (`forumThreadNameRequired`). Any other kind of channel refuses a title.

## Options [#options]

None of these is required. Each one goes with every part, except **Forum post title**, which only the first part takes. **API name** is the option's name in the API:

| Option                                      | API name         | Values                           | Left out |
| ------------------------------------------- | ---------------- | -------------------------------- | -------- |
| **Notify the people and roles it mentions** | `mentions`       | Yes or no                        | No       |
| **Send without a notification**             | `silent`         | Yes or no                        | No       |
| **Show no preview of its links**            | `suppressEmbeds` | Yes or no                        | No       |
| **Forum post title**                        | `threadName`     | One line, 100 characters at most | None     |

## Edit and delete [#live]

Peal can edit a post's text on Discord, and delete the post with every part of it (see [After a post is published](/guides/posts/published)). An edit keeps the files.

Only the webhook that sent a post can change it. If you reconnect the channel with another webhook, Peal doesn't ask Discord to change the posts the old one sent, and it tells you so (`webhookChanged`). Edit or remove those posts on Discord.

## When an answer is lost [#lost]

Discord has no key that lets Peal send a message again safely, and a webhook can't list the channel's messages. So when Discord takes a post and its answer never reaches Peal, the post shows **To check**. Look at the channel, then confirm the post or send it again from its page.

Peal never sends it again on its own, and it doesn't send the parts that come after it.

## What Peal doesn't do on Discord [#limits]

Peal doesn't read anything back from Discord, so there are no counts, replies or inbox for it. It doesn't post in an existing thread, and it sends no embeds, polls or buttons.
