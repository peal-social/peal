You connect a DEV (dev.to) account with an API key you make on DEV, so the Peal server needs no app for it. DEV takes [articles](/guides/channels/websites) rather than posts.

## At a glance [#at-a-glance]

Here's what an article on DEV can hold, and what Peal can do with it:

|             |                                                          |
| ----------- | -------------------------------------------------------- |
| Title       | 128 characters at most                                   |
| Body        | Written as Markdown by Peal, with its images             |
| Tags        | 4 at most, letters and digits only                       |
| Categories  | None                                                     |
| On the site | Published at once, a draft there, or scheduled there     |
| Unpublish   | Makes the article a draft on DEV again: DEV deletes none |

## Connect an account [#connect]

<Steps>
  <Step title="Make an API key">
    On DEV, open **Settings**, then **Extensions**. Under **DEV Community API
    Keys**, describe the key as Peal and click **Generate API Key**.
  </Step>
  <Step title="Connect it in Peal">
    In **Channels**, under **DEV**, paste the key, then click **Connect DEV**.
  </Step>
</Steps>

Peal checks the key on DEV, then keeps it encrypted, and never shows it again. The channel is the account the key belongs to. If you connect it again with a new key, the new key replaces the old one.

To cut Peal off, revoke the key on DEV. The channel is then marked **Reconnect**.

## Articles [#articles]

Peal writes the body as Markdown, and everything you typed stays text. None of it becomes DEV markup, a Liquid tag (`{% … %}`, `{{ … }}`) or an embed, and an `@name` mentions no one. An address typed in the text shows as text, not as a link, so make links with the editor's link button.

Each image goes to DEV's image upload first, once, and the article shows it from DEV. By default DEV takes 10 uploads an hour per account. An article with more images waits for DEV, and is sent once it can be.

The excerpt becomes the article's description, and the featured image its cover. With **Scheduled there**, Peal gives DEV the time, and DEV publishes the article then.

### Rate limits and lost answers [#limits]

DEV takes one write a second from a server, whatever account it's for. So Peal sends its writes to DEV one at a time, a second apart, for every account together. When DEV asks it to wait a moment, it waits.

When DEV's answer is lost, Peal first looks among your articles for one with the same title and body. It never sends an article twice.

## On your own server [#self-hosting]

DEV needs no app on a self-hosted server, because each member brings a key. See [DEV and Hashnode](/self-hosting/platforms#devto-hashnode).
