Every image and video you attach comes from the workspace's media library, and you put them in the order the post shows them. Peal checks them against each channel's platform when you schedule the post, then sends them with it at its time.

## The media library [#library]

To open the library, click **Media** in a workspace's sidebar. Drop files there, or click to choose them. Large videos go up in parts, and you can cancel an upload or try it again.

Give each file a description for people who can't see it, of up to 2,000 characters. The library takes these files:

| Kind      | Formats               | Largest file |
| --------- | --------------------- | ------------ |
| Images    | JPEG, PNG, GIF, WebP  | 16 MiB       |
| Videos    | MP4, QuickTime (.mov) | 1 GiB        |
| Documents | PDF, up to 300 pages  | 100 MiB      |
| Audio     | MP3, M4A, WAV         | 100 MiB      |

Contributors and above can upload. Editors and above can delete.

### What Peal reads from a file [#probe]

Once a file is stored, Peal reads it once: an image's dimensions, a video's dimensions, duration and codec, an audio file's duration and codec, and a PDF's number of pages. An audio file goes out on no platform: it's kept for a [transcript](#transcribe) or to use elsewhere.

A PDF is a document, which only LinkedIn shows, page by page. Peal stores it and hands it over, and never opens it. A PDF of more than 300 pages, the most LinkedIn takes, isn't ready for posts. One whose pages can't be counted, such as an encrypted file, is kept, and LinkedIn judges it.

An image whose content isn't of the type it was uploaded as is refused, and deleted.

A file Peal couldn't read stays uploaded, with the reason. Completing the upload again (`POST …/media/{mediaId}/complete`) reads it again, unless the reason comes from the file itself: too large, more than 300 pages, or a damaged image or PDF. A video found damaged is read again up to three times in a row, as the store may have failed while it was read. Past that, upload the file again instead. A workspace has two files read at once, and a server eight. One more waits up to 20 seconds, then is refused (`MediaImportBusy`, 429) with its upload completed, so complete it again a moment later. Peal's web app and command line do that themselves.

### Storage on an instance that bills [#storage]

On an instance that bills, each billing account holds a number of bytes of media across its workspaces ([A payment method](/guides/workspace/billing#payment-method)), uploads in progress included. When the workspace has no room for an upload, Peal refuses it before anything is sent. Deleting media makes room.

## Find a file [#find]

The library's toolbar finds files by text in their name or their description, whatever its case, and filters them by kind. Both narrow the list together, newest first, and **Show more** goes on with the same search. A file without a name can be found by its description only. When nothing matches, the library says how many files the search and the kind filter hide, and **Clear** shows them again.

Click a thumbnail to see the file at full size. An image shows whole and a video plays. A document gives a link that opens it in a tab of its own.

### File names [#file-names]

Each file keeps the name it had: the name of the file you uploaded, or the last part of the address it was imported from. For an import, that's the address after its redirects, never its query.

Peal keeps the name composed, as a keyboard types accents, and on one line. It drops the folders before it, control characters and characters that show nothing, and cuts it at 255 characters.

An import whose address ends without an extension, or with a part that looks like a share link's secret, gets no name, so that secret is never kept. Any other address gives its last part as the name, and every member sees it. Import only from an address that holds no secret in its path.

An image the assistant made has no name, and neither does a file added before Peal kept names. The library calls each one by its kind (**Image**, **Video**, **PDF document**).

### From the command line, MCP or the API [#find-api]

You can run the same search from any of these:

- The [command line](/developers/cli/posts#media): `peal media list --search "…" --kind image`.
- An [MCP client](/developers/mcp/tools#tools): the `list_media` tool's `q` and `kind`.
- The API: `GET /api/workspaces/{workspaceId}/media?q=…&kind=…`, with `fileName` in each media it answers.

An upload gives the name as `fileName` when it starts (`POST …/media`). The name is the member's own text, so show it as text.

## Import from an address [#import]

A file that's already online can come into the library without passing through your computer, because the Peal server fetches it itself. All three ways need the right to upload.

<Tabs>
<Tab title="CLI">

```sh
peal media import https://files.example/spring/cover.jpg --alt "A paper catalogue open on a wooden table"
```

See [`peal media import`](/developers/cli/posts#media).

</Tab>
<Tab title="MCP">

The `import_media` tool, from an [MCP client](/developers/mcp/tools#tools).

</Tab>
<Tab title="API">

`POST /api/workspaces/{workspaceId}/media/import`, with the file's `url` and, if you like, its `altText`.

</Tab>
</Tabs>

The server checks the address before it fetches anything. The address must be:

- An `https://` URL on the default port.
- Without a user name or password.
- On a public host: not `localhost`, nor a private network.

The server sends no credentials or cookies. It follows at most three redirects, and checks each one the same way.

Peal reads the file's type from the file itself, whatever its name or what its host says, and the formats and sizes above apply. A link to a page that shows a picture isn't the picture.

The file must arrive within 90 seconds, so upload larger or slower files instead. A workspace imports two files at once, and a server eight. One more is refused (`MediaImportBusy`, 429) until one has finished, so ask again a moment later.

Each import adds a new file, read the same way as an upload. On an instance that bills, it must fit the plan's media storage.

## Generate an image [#generate]

When the workspace has its own [image provider](/guides/workspace#providers), or the instance has an image model, the assistant can make an image from a description, straight into the library. You need the right to use the assistant and the right to upload, so contributors and above.

<Tabs>
<Tab title="Web app">

Click **Generate an image** on the **Media** page, or in the composer's **Choose from the library** dialog, where the new image is then selected.

</Tab>
<Tab title="CLI">

```sh
peal media generate --prompt "A paper catalogue open on a wooden table, morning light" --aspect landscape
```

See [`peal media generate`](/developers/cli/posts#media).

</Tab>
<Tab title="MCP">

The `generate_image` tool, from an [MCP client](/developers/mcp/tools#tools).

</Tab>
<Tab title="API">

`POST /api/workspaces/{workspaceId}/assistant/images`, with the `prompt` and the `aspect` (`square`, `landscape` or `portrait`).

</Tab>
</Tabs>

The description can be 1 to 1,000 characters. When the workspace set its own image provider, the description goes as it is to that provider, with the workspace's key. Otherwise it goes to the image provider the instance's administrator chose. Peal never writes the description or the image to its logs.

<Callout
  type="warning"
  title="The provider receives the description exactly as you typed it"
>
  Write nothing in it that you wouldn't send to that provider.
</Callout>

### What an image costs [#generate-cost]

What an image costs depends on who makes it:

| Made by                                                                             | What it costs                                                                                                                        |
| ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| The workspace's own provider                                                        | Nothing of the assistant's allowance and no meter, on any plan, the free tier and a trial included                                   |
| The instance's model, on an instance that bills                                     | One image of the billing account's month ([Usage meters](/guides/workspace/billing#meters)), given back whenever no image came of it |
| The instance's model, on a plan priced by channels or an instance that doesn't bill | 5 of the day's [assistant requests](/guides/posts/assistant#assistant)                                                               |

On an instance that bills, the instance's model makes no image without a payment method, nor during a trial. Before anything is spent, the plan's media storage must have room for the largest image, 16 MiB.

A workspace asks its own provider for 50 images a day at most, and for two at once. Each one counts, whatever it ends with, and past the day's 50 the answer is `OwnImageLimitReached` (429). The workspace's own provider has slots of its own, so its images never take those of the instance's model.

When no image comes of a request, here's what happens:

- The workspace's own provider refuses it (its key, its account, its model or its address): the answer is `ImageProviderRefused`, and an owner or an admin has to fix the settings. Peal never asks its own model instead.
- The instance's provider couldn't be reached, refused the description or the instance's settings, or the plan's storage filled meanwhile: Peal gives the 5 requests back.
- The provider timed out or gave an unusable answer: the request still counts, because the provider may have made the image.

A workspace makes two images at once, and a server eight. One more is refused (`MediaImportBusy`, 429) until one has finished. The provider has 90 seconds to answer.

### The image in the library [#generated-image]

Peal stores the image exactly as the provider made it, and never re-encodes it, so whatever the provider wrote in the file stays in it. The image gets no description, so say what it shows in its alt text when you attach it.

The library marks it **Made by AI**, and the API's media answers `aiGenerated: true`.

When you attach it in the web app, the composer turns on the AI label of each channel whose platform has one, once, and tells you. Those labels are YouTube's synthetic content, TikTok's AI-generated content and X's made with AI. You can turn the label off in the channel's options.

Peal doesn't set these labels on posts made through the API, the command line or MCP, so set the [platform options](/guides/posts#options) yourself.

Images are off unless the workspace sets its own provider, or the instance sets an image model: see [Self-hosting](/self-hosting/assistant#ai).

## Generate a video [#generate-video]

When the workspace chose a provider and a model for [videos](/guides/workspace#models), the assistant can make a video from a description, straight into the library. Videos come from Google Gemini's Veo models or xAI's Grok Imagine models, with the workspace's own key: the instance has no video model of its own. You need the right to use the assistant and the right to upload, so contributors and above.

<Tabs>
<Tab title="Web app">

Click **Generate a video** on the **Media** page. Describe the video, pick its aspect and, when the provider takes them, its length and an image of the library to start from. The video shows in the library as a placeholder with its state until it's ready.

</Tab>
<Tab title="CLI">

```sh
peal media video generate --prompt "The catalogue's pages turning slowly in the wind" --aspect portrait --wait
```

See [`peal media video`](/developers/cli/posts#media-video).

</Tab>
<Tab title="API">

`POST /api/workspaces/{workspaceId}/media/videos/generations`, with the `prompt`, the `aspect` and, optionally, `durationSeconds` and `imageMediaId`. The answer is `202` with the job. Follow it with `GET /api/workspaces/{workspaceId}/media/videos/generations/{id}` until its `status` is `succeeded`, with the video's `mediaId`, or `failed`, with its `reason`.

</Tab>
</Tabs>

What each provider takes:

| Provider      | Aspects                                 | Length          | First frame |
| ------------- | --------------------------------------- | --------------- | ----------- |
| Google Gemini | `landscape` (16:9), `portrait` (9:16)   | chosen by Veo   | yes         |
| xAI           | `landscape`, `portrait`, `square` (1:1) | 1 to 15 seconds | yes         |

The description can be 1 to 1,000 characters, and goes as it is to the provider, with the workspace's key. Peal keeps it only while the video is made, then erases it, and never writes it or the video to its logs.

<Callout type="warning" title="Your provider bills each video">
  Peal bills nothing for videos, but your account at the provider pays for each
  one it makes, at its prices. Making a video takes minutes.
</Callout>

### How a video is made [#video-job]

A video is a job that runs on the server, so you can leave the page. It's `queued`, then `running` while the provider makes it, then `succeeded` or `failed`. When it ends, the member who asked gets a notice in the app.

- A workspace makes one video at a time. Asking for another meanwhile is refused (`VideoBusy`, 429).
- A workspace asks for 20 videos a day at most (UTC), whatever each ends with (`VideoAllowanceReached`, 429).
- Before anything is asked, the plan's media storage must have room for the largest video Peal keeps, 200 MiB. The video then takes room like any other file.
- Peal waits up to 15 minutes for the provider. A server makes four videos at once; the others wait their turn, queued.
- Peal never asks the provider twice for one video. If the server stops while a video is made, the video fails as `interrupted`, because the provider may already have made and billed it. Ask for it again if you want it.

<Accordion>
<AccordionItem title="Why a video failed">

| Reason             | What happened                                                              |
| ------------------ | -------------------------------------------------------------------------- |
| `unavailable`      | No provider is chosen for videos any more                                  |
| `keyUnreadable`    | The provider's key can't be read any more: connect the provider again      |
| `settingsRefused`  | The provider refused the key, the account or the model                     |
| `addressRefused`   | The provider's address isn't one Peal sends to                             |
| `redirected`       | The provider answered with a redirect, which Peal never follows            |
| `unreachable`      | The provider couldn't be reached, or was busy                              |
| `refused`          | The provider refused this request, such as for its content rules           |
| `timedOut`         | The video took longer than 15 minutes                                      |
| `unusableAnswer`   | The provider's answer held no video Peal keeps, or one larger than 200 MiB |
| `imageUnavailable` | The first frame was deleted, or couldn't be read                           |
| `storageFull`      | The plan's media storage had no room for it                                |
| `notStored`        | The media store failed to keep it                                          |
| `interrupted`      | The server stopped while it was made                                       |

</AccordionItem>
</Accordion>

The video is an MP4 file in the library, marked **Made by AI** (`aiGenerated: true` in the API), with no description. As for an image, set the platform's AI label in the post's options when Peal doesn't. No MCP tool makes videos, because each one is paid by the workspace's account at the provider.

## Create a voice-over [#voiceover]

When the workspace chose a provider and a model for [voice-overs](/guides/workspace#models), the assistant can speak a text into the library, as an audio file. Voice-overs come from OpenAI, Google Gemini, Mistral, xAI, ElevenLabs or fal, with the workspace's own key: the instance has none of its own. You need the right to use the assistant and the right to upload, so contributors and above.

<Tabs>
<Tab title="Web app">

Click **Create a voice-over** on the **Media** page. Write the text and, when the provider takes one, pick a voice, or type a voice's ID for ElevenLabs. The audio file shows in the library once it's made.

</Tab>
<Tab title="CLI">

```sh
peal media voiceover --text "Welcome to the spring catalogue." --voice nova
```

See [`peal media voiceover`](/developers/cli/posts#media-audio).

</Tab>
<Tab title="API">

`POST /api/workspaces/{workspaceId}/media/voiceovers`, with the `text` and, optionally, a `voice`. The answer is `201` with the new file of the library.

</Tab>
</Tabs>

The text can be 1 to 4,000 characters, and goes as it is to the provider. The voices each provider takes:

| Provider      | Voices                                                                      |
| ------------- | --------------------------------------------------------------------------- |
| OpenAI        | `alloy`, `ash`, `coral`, `echo`, `fable`, `onyx`, `nova`, `sage`, `shimmer` |
| Google Gemini | `Kore`, `Puck`, `Zephyr`, `Charon` and its other prebuilt voices            |
| Mistral       | `gb_jane_neutral` and its other preset voices                               |
| xAI           | `eve`, `ara`, `rex`, `sal`, `leo`                                           |
| ElevenLabs    | the ID of any voice of your account's library                               |
| fal           | none: its MiniMax models speak with their own voice                         |

Left out, the provider's default voice speaks. The voice-over is an MP3 file (a WAV file for Google Gemini), marked **Made by AI**, with no description. A workspace makes 50 a day at most (UTC), whatever each ends with (`AudioAllowanceReached`, 429). Before anything is asked, the plan's storage must have room for the largest voice-over Peal keeps, 48 MiB. Peal waits 90 seconds for the provider. Neither the text nor the audio goes to Peal's logs.

No platform takes an audio file on its own: use the voice-over in a video you make, or elsewhere.

## Transcribe a file [#transcribe]

When the workspace chose a provider and a model for [transcription](/guides/workspace#models), the assistant can write what is said in an audio or video file of the library. Transcripts come from OpenAI, Google Gemini, Mistral, xAI, Groq, ElevenLabs or fal, with the workspace's own key. You need the right to use the assistant and the right to read media; saving the transcript as the file's description also takes the right to upload.

<Tabs>
<Tab title="Web app">

On an audio or video file of the **Media** page, click the transcript button, then **Transcribe**. The transcript shows in the dialog, with **Copy** and **Use as description**.

</Tab>
<Tab title="CLI">

```sh
peal media transcribe <media-id> --save-description
```

</Tab>
<Tab title="API">

`POST /api/workspaces/{workspaceId}/media/{mediaId}/transcription`, with `saveAsDescription` when the transcript should become the file's description. The answer holds the `text`, the `language` and the `durationSeconds` when the provider gives them, and `descriptionSaved`.

</Tab>
</Tabs>

The file must be ready and at most 25 MB (`TranscriptionRejected`, 422, otherwise). Peal reads it from the media store and sends it whole to the provider, which can take a minute for a long recording: Peal waits 90 seconds. A workspace asks for 50 transcripts a day at most (UTC), whatever each ends with. A transcript is saved as the description only when it fits one, 2,000 characters; otherwise it's answered and nothing changes. Peal keeps the transcript nowhere else, and never writes it to its logs.

<Callout
  type="warning"
  title="Your provider bills each voice-over and transcript"
>
  Peal bills nothing for them, but your account at the provider pays for each
  one, at its prices. No MCP tool makes them.
</Callout>

## Make a slide video [#make-a-slide-video]

A slide video puts 2 to 10 images of the library one after the other, each with an optional caption and a slow motion, over an optional voice-over, into one MP4 file. Shotstack composes it with the workspace's own key, once the workspace [connected Shotstack](/guides/workspace#shotstack) and chose it for slide videos. You need the right to use the assistant and the right to upload, so contributors and above.

<Tabs>
<Tab title="Web app">

Click **Make a slide video** on the **Media** page. Pick the images in the order they show, and move them up or down. Give each a caption and a motion if you want them, then choose a voice-over from the library, the aspect, how long each slide shows and the transition. The video shows in the library as a placeholder with its state until it's ready.

To build a video yourself, open **Studio** > **Editor** in the sidebar instead. Choose **Add files** for pictures, videos and sounds from the library, or add text with the button beside the preview, then arrange them on tracks: drag a clip to move it, drag its edges to trim it, and the first track shows on top. Choose a clip to change it with the toolbar over the preview. The editor is Shotstack Studio, and its controls are in English. Your work is kept in this browser until you start over. **Export video** sends it to your workspace's Shotstack account, and the video lands in **Media**.

</Tab>
<Tab title="CLI">

```sh
peal media slideshow create \
  --image <media-id> --caption "Spring catalogue" --motion zoomIn \
  --image <media-id> --caption "Out on Friday" --motion slide \
  --voiceover <media-id> --aspect portrait --wait
```

See [`peal media slideshow`](/developers/cli/posts#media-slideshow).

</Tab>
<Tab title="API">

`POST /api/workspaces/{workspaceId}/media/slideshows`, with the `aspect` and the `slides`, each a `mediaId` with an optional `caption` and `motion`, and optionally `secondsPerSlide`, `transition` and `voiceoverMediaId`. The answer is `202` with the job. Follow it with `GET /api/workspaces/{workspaceId}/media/slideshows/{id}` until its `status` is `succeeded`, with the video's `mediaId`, or `failed`, with its `reason`.

</Tab>
</Tabs>

What a slide video takes:

| Setting           | Values                                                           | Default                                    |
| ----------------- | ---------------------------------------------------------------- | ------------------------------------------ |
| Images            | 2 to 10 ready JPEG or PNG images of the library, in order        | required                                   |
| Caption           | up to 120 characters a slide, white on a dark band at the bottom | none                                       |
| Motion            | `none`, `zoomIn`, `zoomOut` or `slide` (a slow pan), a slide     | `none`                                     |
| Transition        | `fade` or `none`, between every two slides                       | `fade`                                     |
| Voice-over        | a ready audio file of the library                                | none                                       |
| Seconds per slide | 2 to 10, 90 seconds in all                                       | the voice-over shared between them, else 4 |
| Aspect            | `portrait` (9:16), `landscape` (16:9) or `square` (1:1)          | `portrait` in the app and the CLI          |

The video is 1080 pixels on its short side, at 25 frames a second. With a voice-over and no seconds given, each slide lasts the voice-over's length divided by the number of slides, which must give 2 to 10 seconds a slide. With seconds given, the voice-over stops at the last slide's end.

<Callout type="warning" title="Your Shotstack account pays for each render">
  Peal bills nothing for slide videos, and your Shotstack account pays for each
  one at its prices. On Peal Cloud, they also need a payment method on the
  workspace's billing account: on the free tier, **Make a slide video** opens
  the upgrade dialog, and the API answers `CompositionNeedsPayment` (402).
</Callout>

### How a slide video is made [#slideshow-job]

A slide video is a job that runs on the server, so you can leave the page. It's `queued`, then `running` while Shotstack renders it, then `succeeded` or `failed`. When it ends, the member who asked gets a notice in the app.

- Peal sends Shotstack the slides with a link to each file, which works for an hour, and the captions. It asks Shotstack not to host the video it renders, then fetches the video and keeps it in the library.
- Shotstack fetches those links itself, from the internet, so the media storage must be reachable from it. On a self-hosted server whose S3 store is on a private network, Shotstack refuses every slide video (`refused`).
- A workspace makes one slide video at a time (`CompositionBusy`, 429) and 20 a day at most (UTC), whatever each ends with (`CompositionAllowanceReached`, 429).
- Before anything is asked, the plan's media storage must have room for 200 MiB. The video then takes room like any other file.
- Peal reads where the render stands every 5 seconds, for up to 20 minutes.
- Peal never asks Shotstack twice for one video. If the server stops while a video is made, it fails as `interrupted`, because Shotstack may already have rendered and billed it.

<Accordion>
<AccordionItem title="Why a slide video failed">

| Reason             | What happened                                                                    |
| ------------------ | -------------------------------------------------------------------------------- |
| `unavailable`      | No service is chosen for slide videos any more                                   |
| `keyUnreadable`    | The Shotstack key can't be read any more: connect Shotstack again                |
| `settingsRefused`  | Shotstack refused the key or the account, as when it has no credits left         |
| `addressRefused`   | The service's address isn't one Peal sends to                                    |
| `redirected`       | Shotstack answered with a redirect, which Peal never follows                     |
| `unreachable`      | Shotstack couldn't be reached, or was busy                                       |
| `refused`          | Shotstack refused this request, couldn't fetch its files, or failed to render it |
| `timedOut`         | The video took longer than 20 minutes                                            |
| `unusableAnswer`   | Shotstack's answer held no video Peal keeps, or one larger than 200 MiB          |
| `mediaUnavailable` | An image or the voice-over was deleted, or couldn't be handed to Shotstack       |
| `storageFull`      | The plan's media storage had no room for it                                      |
| `notStored`        | The media store failed to keep it                                                |
| `interrupted`      | The server stopped while it was made                                             |

</AccordionItem>
</Accordion>

The video is an MP4 file in the library, with no description. It isn't marked as made by AI, since Shotstack only puts your own files together. Peal never writes the captions or the video to its logs, and keeps the captions only while the video is made. No MCP tool makes slide videos, because each one is paid by the workspace's Shotstack account.

### Render an edit through the API [#render-an-edit]

A program, or a video editor that writes Shotstack's format, can send a whole [Shotstack Edit](https://shotstack.io/docs/api/#tocs_edit) instead of a list of images. Peal checks it and renders it with the workspace's Shotstack connection, as the same job as a slide video, with the same rights.

Send `POST /api/workspaces/{workspaceId}/media/slideshows/edits` with the edit in `edit`. The answer is `202` with the job, which you follow as above. The job's `durationSeconds` is the latest end of a clip whose start and length are numbers, and its `imageMediaIds` lists every library file the edit names, images or not.

```json
{
  "edit": {
    "timeline": {
      "tracks": [
        {
          "clips": [
            {
              "asset": { "type": "rich-text", "text": "Out on Friday" },
              "start": 0,
              "length": 3
            }
          ]
        },
        {
          "clips": [
            {
              "asset": { "type": "image", "src": "peal:media/<media-id>" },
              "start": 0,
              "length": 4
            },
            {
              "asset": { "type": "video", "src": "peal:media/<media-id>" },
              "start": 4,
              "length": 6
            }
          ]
        }
      ]
    },
    "output": { "aspectRatio": "9:16" }
  }
}
```

Name each file of the library `peal:media/<media-id>`. It must be a ready file of a kind its asset takes: an image for an image asset, a video for a video asset, an audio file for an audio asset or the soundtrack, an audio or video file for captions, and an image or a video for a luma matte. Fonts may also come from `https://fonts.gstatic.com/`. An asset Shotstack generates from a `prompt` needs no file. Any other address is refused, and so are merge fields.

| Setting              | Values                                                                 | Default             |
| -------------------- | ---------------------------------------------------------------------- | ------------------- |
| `output.format`      | `mp4`                                                                  | `mp4`               |
| `output.resolution`  | `preview`, `mobile`, `sd`, `hd` or `1080`                              | `1080`              |
| `output.aspectRatio` | `16:9`, `9:16` or `1:1`, the job's `landscape`, `portrait` or `square` | `16:9`              |
| `output.fps`         | up to 30                                                               | Shotstack's default |
| Tracks               | up to 20                                                               |                     |
| Clips                | up to 200 in all                                                       |                     |
| Length               | every clip whose start and length are numbers ends by 300 seconds      |                     |

The output takes no `size`, `range`, `scaleTo`, `repeat`, `poster` or `thumbnail`. Peal replaces the destinations so that Shotstack hosts no copy, turns the timeline's cache off, and drops `callback` and `disk`. A refused edit is `SlideshowRequestRejected` (422), and nothing is asked or counted:

| Reason               | What happened                                                                                |
| -------------------- | -------------------------------------------------------------------------------------------- |
| `editInvalid`        | Shotstack's schema refuses the edit, it merges fields, or it names a file at another address |
| `mediaNotFound`      | A `peal:media/` file isn't a ready file of the workspace's library                           |
| `mediaNotSupported`  | A library file is of a kind its asset can't take, such as an audio file as an image          |
| `outputNotSupported` | The output isn't one Peal renders                                                            |
| `editTooLarge`       | The edit has more than 20 tracks or 200 clips                                                |
| `editTooLong`        | A clip ends past 300 seconds                                                                 |

Peal never writes the edit to its logs, and keeps it only while the video is rendered.

## Attach media to a post [#attach]

In the composer, files go under **Images and videos**. A post holds up to 20 images and videos, and each platform takes fewer, as listed [below](#platforms). Saving the draft keeps them.

### Pick from the library [#attach-library]

Click **Choose from the library** to open the workspace's media. Select files in the order the post shows them, and each gets a number as you go. Then click **Attach**.

Files that are still being processed are marked **Not ready yet**, and you can't select them.

### Upload from the composer [#attach-upload]

Drop files on the uploader below, or click it to choose them. Each file joins the post once it's uploaded and read.

A file that's uploaded but can't be read yet, such as a video on a server without ffprobe, stays in the library and isn't attached.

### Reorder or remove a file [#attach-order]

Move a file earlier or later in the post with its arrows, or remove it from the post. Removing it leaves it in the library.

## Alt text [#alt-text]

Each image or video in a post has its own alt text, which starts as its description in the library. Changing it in the composer changes it for this post only. A post's alt text can be up to 5,000 characters, but platforms keep less, as listed below.

Write alt text for every file. When one has none, the composer names the platforms among the post's channels that show alt text, and each of those channels shows how many files lack it.

<Callout type="info" title="Missing alt text doesn't stop you from scheduling">
  The composer only reminds you.
</Callout>

## What each platform accepts [#platforms]

When you schedule a post, Peal checks its images and videos against these limits.

### Bluesky and Mastodon [#platforms-bluesky-mastodon]

Here's what Bluesky and Mastodon take:

| Limit                         | Bluesky                                             | Mastodon                                                                  |
| ----------------------------- | --------------------------------------------------- | ------------------------------------------------------------------------- |
| Images and videos in one post | 4                                                   | 4                                                                         |
| Images                        | JPEG, PNG, GIF and WebP, up to 2,000,000 bytes each | JPEG, PNG, GIF and WebP, up to 16 MiB and 33,177,600 pixels (7680 × 4320) |
| Videos                        | One MP4, up to 300,000,000 bytes and 3 minutes      | One MP4 or QuickTime, up to 99 MiB and 8,294,400 pixels (3840 × 2160)     |
| Images and a video together   | No                                                  | No                                                                        |
| Alt text                      | Shown to people who need it                         | Shown to people who need it, up to 1,500 characters                       |

The Mastodon limits are those of a Mastodon server as it comes. When the post goes out, Peal also reads the limits of the account's own server: the file types it takes, and its largest image and video. Peal doesn't send a file that server would refuse, and the post then fails on that channel.

### LinkedIn and X [#platforms-linkedin-x]

Here's what LinkedIn and X take:

| Limit                         | LinkedIn                                                       | X                                                          |
| ----------------------------- | -------------------------------------------------------------- | ---------------------------------------------------------- |
| Images and videos in one post | 20                                                             | 4, or one GIF alone                                        |
| Images                        | JPEG, PNG and GIF, up to 36,152,320 pixels                     | JPEG, PNG and WebP up to 5 MiB; GIF up to 15 MiB           |
| Videos                        | One MP4, of 3 seconds to 30 minutes, from 75 KB to 500 MiB     | One MP4 or QuickTime, of 0.5 to 140 seconds, up to 512 MiB |
| Images and a video together   | No                                                             | No                                                         |
| Alt text                      | On images, shown to people who need it, up to 4,086 characters | Shown to people who need it, up to 1,000 characters        |

X lets some accounts post longer videos, but Peal checks the length every account can post. A GIF with other files on X, and a video under 75 KB (75,000 bytes) on LinkedIn, are refused when the post is scheduled.

On LinkedIn, a post can show one PDF of up to 100 MiB instead, on its own and without alt text. It shows under the title its options give, or its file's name. Every other platform refuses a PDF when the post is scheduled.

Peal uploads each image to Slack before the message that shows it, without sharing it anywhere. The images sit under the message's text, which can be up to 3,000 characters.

## When you schedule [#schedule]

Next to each channel's counter, the composer lists what its platform would refuse:

- Too many videos, or images with a video.
- A file type it doesn't take.
- A file too large, a video too long or too short, or too many pixels.
- A shape it doesn't take.
- Alt text that's too long.

You can't click **Schedule** until each one is fixed, and the composer names the channel and the image or video concerned.

A draft can hold any ready media of its workspace, because the platforms' limits wait until you schedule it. Moving a scheduled post doesn't check its media again. On the calendar, posts with images or videos carry a mark.

## When the post goes out [#publishing]

At the post's time, Peal sends each file from the library to the platform, then publishes the post. Peal waits up to 15 minutes for a platform to process a file. Past that, it tries the post again later, as for a platform that doesn't answer. A YouTube video that's already uploaded is left published while YouTube finishes.

Each platform takes the files its own way:

<Accordion>
  <AccordionItem title="Mastodon">
    Each file goes to the account's server, which may process it before the post
    can show it.
  </AccordionItem>
  <AccordionItem title="Bluesky">
    Images go to the server that holds the account, and a video goes to
    Bluesky's video service, which processes it.
  </AccordionItem>
  <AccordionItem title="Threads, Instagram and Facebook Pages">
    Peal gives Meta a link to each file in the media store, valid for two hours,
    and Meta fetches it. On Threads and Instagram, Meta then processes the files
    before the post goes out.
  </AccordionItem>
  <AccordionItem title="TikTok">
    A video goes up in parts of 10 MB, read one at a time from the media store,
    unless the server lets TikTok fetch it from the store's public address.
    TikTok always fetches photos. TikTok then processes the post before it goes
    live.
  </AccordionItem>
  <AccordionItem title="YouTube">
    Peal uploads the video in parts of 8 MiB. If an upload is cut off, Peal
    picks up where YouTube stands, even after the server restarts. Then it waits
    while YouTube processes the video.
  </AccordionItem>
  <AccordionItem title="Pinterest">
    Peal gives Pinterest a link to each image in the media store, valid for two
    hours, and Pinterest fetches it when it creates the Pin. A video goes up in
    one request to the address Pinterest gives for it. Peal reads it from the
    media store as it sends it, and never holds it whole in memory. Pinterest
    then processes it, usually within seconds.
  </AccordionItem>
  <AccordionItem title="Google Business Profile">
    Peal gives Google a link to each photo in the media store, valid for two
    hours, and Google fetches it.
  </AccordionItem>
</Accordion>

## Delete media [#delete]

<Steps>
  <Step title="Click Delete on the file">
    In the library, click **Delete** (the bin) on a file. The dialog says which
    posts show it.
  </Step>
  <Step title="Confirm">Click **Delete** to delete the file.</Step>
</Steps>

You can't delete a file while a post that's scheduled, or going out, shows it. The dialog links to those posts. Take each one back to draft and remove the file, or wait until it has gone out.

Drafts that show the file lose it when you delete it, and the dialog says how many. Posts that went out keep the file on their platforms.

A file can count as one a post shows in two other ways:

- A post's [options](/platforms) name it, as a YouTube video's thumbnail or an Instagram reel's cover. You can't delete it while such a post is scheduled or going out, and a draft that names it loses it.
- A post shows it on one channel only, as [images and videos of its own](/guides/posts#write) there. A draft's channel whose only file it was shows the post's images and videos again.

<Callout
  type="warning"
  title="A file deleted from under a post makes the post fail"
>
  If a file is still deleted from under a post at its time, the post fails on
  its channels, saying an image or video was deleted.
</Callout>
