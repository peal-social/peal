Les SDK de Peal appellent l’[API](/developers) depuis huit langages. Ils sont générés à partir du même contrat que le serveur : chaque méthode porte le nom d’une opération de l’API (`posts.send`, `media.importFromUrl`), et chaque type celui d’un schéma. Contrairement au reste de Peal, ce sont des logiciels libres, sous licence Apache 2.0.

## Installer [#install]

Chaque SDK est publié sur le registre de son langage :

| Langage               | Registre                                                                          | Installation                                              |
| --------------------- | --------------------------------------------------------------------------------- | --------------------------------------------------------- |
| TypeScript/JavaScript | [npm](https://www.npmjs.com/package/peal-sdk)                                     | `npm install peal-sdk`                                    |
| Python                | [PyPI](https://pypi.org/project/peal-sdk/)                                        | `pip install peal-sdk` (importé sous `peal`)              |
| Go                    | [Go modules](https://pkg.go.dev/github.com/peal-social/peal/packages/peal-sdk/go) | `go get github.com/peal-social/peal/packages/peal-sdk/go` |
| Ruby                  | [RubyGems](https://rubygems.org/gems/peal)                                        | `gem install peal`                                        |
| Java                  | [Maven Central](https://central.sonatype.com/artifact/social.peal/peal)           | `social.peal:peal`                                        |
| PHP                   | [Packagist](https://packagist.org/packages/peal-social/peal)                      | `composer require peal-social/peal`                       |
| .NET                  | [NuGet](https://www.nuget.org/packages/Peal)                                      | `dotnet add package Peal`                                 |
| Rust                  | [crates.io](https://crates.io/crates/peal-sdk)                                    | `cargo add peal-sdk`                                      |

Le README de chaque paquet montre comment s’en servir, et son `reference.md` liste chaque méthode. Vous trouverez les deux dans [le dépôt](https://github.com/peal-social/peal/tree/main/packages/peal-sdk).

Les SDK appellent tous les points d’accès qui acceptent un jeton porteur. C’est une [clé d’API](/guides/workspace#api-keys) (`peal_…`), une [clé partenaire](/developers/embedding) (`peal_partner_…`) ou un jeton d’accès OAuth. Ce que seule une personne fait dans sa propre session en est exclu : exporter ou supprimer un compte, et les applications connectées.

### Le diriger vers votre serveur [#base-url]

Les SDK envoient leurs requêtes à `https://app.peal.social`. Sur votre propre serveur, donnez son adresse au client ([URL de base](/developers#base-url)) avec cette option :

| Langage            | Option                         |
| ------------------ | ------------------------------ |
| TypeScript et PHP  | `baseUrl`, dans les options    |
| Python, Ruby, Rust | `base_url`                     |
| Go                 | `option.WithBaseURL`           |
| Java               | `.url(…)` sur le constructeur  |
| .NET               | `BaseUrl` dans `ClientOptions` |

## Vérifier d’abord l’identifiant [#credential]

Commencez par `GET /api/credential`. Il vous dit qui est la clé ou le jeton, et ce qu’il peut faire, sans lire aucune donnée. Une clé révoquée ou expirée reçoit 401 : votre programme sait donc si sa clé fonctionne avant de faire quoi que ce soit.

La réponse dépend de l’identifiant :

| Identifiant             | Répond       | Avec                                                                    |
| ----------------------- | ------------ | ----------------------------------------------------------------------- |
| Une clé d’API           | `apiKey`     | Son nom, son espace de travail, ses permissions et sa date d’expiration |
| Une clé partenaire      | `partnerKey` | Son partenaire, ses portées et ses permissions                          |
| Le jeton d’une personne | `user`       |                                                                         |

Créez le client à partir de votre clé, puis demandez qui elle est :

## Publier, de bout en bout [#journey]

Ce programme suit les étapes de l’[API de publication](/developers/posting). Il trouve les canaux, importe une image depuis son adresse, vérifie la publication, l’envoie avec une `Idempotency-Key`, puis lit comment elle s’est passée. L’identifiant de l’espace de travail est celui qu’a renvoyé la vérification de l’identifiant.

<CodeGroup>

```ts Node.js
import { randomUUID } from "node:crypto";

import { PealClient } from "peal-sdk";

const peal = new PealClient({ token: process.env.PEAL_API_KEY });
const workspaceId = process.env.PEAL_WORKSPACE_ID ?? "";

// 1. Où elle peut partir : les canaux qui peuvent publier.
const channels = await peal.channels.list({ workspaceId });
const channelIds = channels
  .filter(({ status }) => status._tag === "active")
  .map(({ id }) => id);

// 2. Une image déjà en ligne. Le serveur va la chercher lui-même.
const image = await peal.media.importFromUrl({
  workspaceId,
  url: "https://media.example.com/synthetic/launch.png",
  altText: "A synthetic launch picture",
});

const post = {
  workspaceId,
  channelIds,
  content: {
    text: "A synthetic post, sent with the SDK.",
    media: [{ mediaId: image.id, altText: "A synthetic launch picture" }],
    overrides: [],
  },
  when: { _tag: "now" as const },
};

// 3. Vérifiée sans être créée, avec toutes les violations d’un coup.
const check = await peal.posts.validate(post);

if (!check.valid) {
  throw new Error(JSON.stringify(check.violations));
}

// 4. Envoyée sous une clé : une nouvelle tentative avec la même clé dans les
// 24 heures renvoie cette publication, sans en créer une deuxième.
const sent = await peal.posts.send({
  ...post,
  "idempotency-key": randomUUID(),
  wait: "30",
});

// 5. Comment elle s’est passée sur chaque canal, une fois que chacun a son
// résultat.
const outcome = await peal.posts.outcome({ workspaceId, postId: sent.id });

for (const target of outcome.targets) {
  console.log(target.channelId, target.status, target.permalink);
}
```

```go Go
package main

import (
	"context"
	"crypto/rand"
	"fmt"
	"os"

	peal "github.com/peal-social/peal/packages/peal-sdk/go"
	"github.com/peal-social/peal/packages/peal-sdk/go/client"
	"github.com/peal-social/peal/packages/peal-sdk/go/option"
)

func main() {
	ctx := context.Background()
	client := client.NewClient(option.WithToken(os.Getenv("PEAL_API_KEY")))
	workspaceID := os.Getenv("PEAL_WORKSPACE_ID")

	// 1. Où elle peut partir : les canaux qui peuvent publier.
	channels, err := client.Channels.List(ctx, &peal.ListChannelsRequest{WorkspaceID: workspaceID})
	if err != nil {
		panic(err)
	}

	var channelIDs []string
	for _, channel := range channels {
		if channel.Status.Active != nil {
			channelIDs = append(channelIDs, channel.ID)
		}
	}

	// 2. Une image déjà en ligne. Le serveur va la chercher lui-même.
	image, err := client.Media.ImportFromURL(ctx, &peal.MediaImport{
		WorkspaceID: workspaceID,
		URL:         "https://media.example.com/synthetic/launch.png",
		AltText:     peal.String("A synthetic launch picture"),
	})
	if err != nil {
		panic(err)
	}

	content := &peal.PostContent{
		Text: "A synthetic post, sent with the SDK.",
		Media: []*peal.MediaAttachment{
			{MediaID: image.ID, AltText: "A synthetic launch picture"},
		},
		Overrides: []*peal.TextOverride{},
	}
	now := &peal.PostTiming{Now: &peal.PostTimingNow{}}

	// 3. Vérifiée sans être créée, avec toutes les violations d’un coup.
	check, err := client.Posts.Validate(ctx, &peal.PostToValidate{
		WorkspaceID: workspaceID,
		ChannelIDs:  channelIDs,
		Content:     content,
		When:        now,
	})
	if err != nil {
		panic(err)
	}
	if !check.Valid {
		panic(fmt.Sprint(check.Violations))
	}

	// 4. Envoyée sous une clé : une nouvelle tentative avec la même clé dans
	// les 24 heures renvoie cette publication, sans en créer une deuxième.
	sent, err := client.Posts.Send(ctx, &peal.NewPost{
		WorkspaceID:    workspaceID,
		ChannelIDs:     channelIDs,
		Content:        content,
		When:           now,
		IdempotencyKey: peal.String(rand.Text()),
		Wait:           peal.String("30"),
	})
	if err != nil {
		panic(err)
	}

	// 5. Comment elle s’est passée sur chaque canal, une fois que chacun a
	// son résultat.
	outcome, err := client.Posts.Outcome(ctx, &peal.OutcomePostsRequest{
		WorkspaceID: workspaceID,
		PostID:      sent.ID,
	})
	if err != nil {
		panic(err)
	}

	for _, target := range outcome.Targets {
		permalink := ""
		if target.Permalink != nil {
			permalink = *target.Permalink
		}
		fmt.Println(target.ChannelID, target.Status, permalink)
	}
}
```

```java Java
import java.util.List;
import java.util.UUID;
import social.peal.PealClient;
import social.peal.resources.media.requests.MediaImport;
import social.peal.resources.posts.requests.NewPost;
import social.peal.resources.posts.requests.PostToValidate;
import social.peal.types.Channel;
import social.peal.types.Media;
import social.peal.types.MediaAttachment;
import social.peal.types.Post;
import social.peal.types.PostContent;
import social.peal.types.PostTarget;
import social.peal.types.PostTiming;
import social.peal.types.PostTimingNow;
import social.peal.types.PostValidation;

PealClient peal = PealClient.builder()
    .token(System.getenv("PEAL_API_KEY"))
    .build();
String workspaceId = System.getenv("PEAL_WORKSPACE_ID");

// 1. Où elle peut partir : les canaux qui peuvent publier.
List<String> channelIds = peal.channels().list(workspaceId).stream()
    .filter(channel -> channel.getStatus().isActive())
    .map(Channel::getId)
    .toList();

// 2. Une image déjà en ligne. Le serveur va la chercher lui-même.
Media image = peal.media().importFromUrl(workspaceId, MediaImport.builder()
    .url("https://media.example.com/synthetic/launch.png")
    .altText("A synthetic launch picture")
    .build());

PostContent content = PostContent.builder()
    .text("A synthetic post, sent with the SDK.")
    .media(List.of(MediaAttachment.builder()
        .altText("A synthetic launch picture")
        .mediaId(image.getId())
        .build()))
    .build();
PostTiming now = PostTiming.now(PostTimingNow.builder().build());

// 3. Vérifiée sans être créée, avec toutes les violations d’un coup.
PostValidation check = peal.posts().validate(workspaceId, PostToValidate.builder()
    .content(content)
    .channelIds(channelIds)
    .when(now)
    .build());

if (!check.getValid()) {
    throw new IllegalStateException(check.getViolations().toString());
}

// 4. Envoyée sous une clé : une nouvelle tentative avec la même clé dans les
// 24 heures renvoie cette publication, sans en créer une deuxième.
Post sent = peal.posts().send(workspaceId, NewPost.builder()
    .content(content)
    .when(now)
    .channelIds(channelIds)
    .idempotencyKey(UUID.randomUUID().toString())
    .wait("30")
    .build());

// 5. Comment elle s’est passée sur chaque canal, une fois que chacun a son
// résultat.
Post outcome = peal.posts().outcome(workspaceId, sent.getId());

for (PostTarget target : outcome.getTargets()) {
    System.out.println(target.getChannelId() + " " + target.getStatus() + " "
        + target.getPermalink().orElse(""));
}
```

```rust Rust
                .channel_ids(channel_ids.clone())
                .content(content.clone())
                .when(PostTiming::now())
                .build()?,
            None,
        )
        .await?;

    if !check.valid {
        return Err(format!("{:?}", check.violations).into());
    }

    // 4. Envoyée sous une clé : une nouvelle tentative avec la même clé dans
    // les 24 heures renvoie cette publication, sans en créer une deuxième.
    // NewPost n’a pas de champ pour la clé, qui passe donc dans les en-têtes
    // de la requête.
    let sent = peal
        .posts
        .send(
            &workspace_id,
            &NewPost::builder()
                .channel_ids(channel_ids)
                .content(content)
                .when(PostTiming::now())
                .wait("30")
                .build()?,
            Some(RequestOptions::new().additional_header(
                "Idempotency-Key",
                uuid::Uuid::new_v4().to_string(),
            )),
        )
        .await?;

    // 5. Comment elle s’est passée sur chaque canal, une fois que chacun a
    // son résultat.
    let outcome = peal
        .posts
        .outcome(&workspace_id, &sent.id, &OutcomeQueryRequest::default(), None)
        .await?;

    for target in outcome.targets {
        println!("{} {} {:?}", target.channel_id, target.status, target.permalink);
    }

    Ok(())
}
```

</CodeGroup>

| ---------------------- | ------------------------------- | ------------------------------- | --------------------------------- | --------------------------------- | -------------------------------- | ------------------------------------ | ---------------------------------------------------------------- |
| Vérifier l’identifiant | `credential.get`                | `Credential.Get`                | `credential.get`                  | `credential().get`                | `credential->get`                | `Credential.GetAsync`                | `credential.get`                                                 |
| Lister les canaux      | `channels.list`                 | `Channels.List`                 | `channels.list`                   | `channels().list`                 | `channels->list`                 | `Channels.ListAsync`                 | `channels.list`                                                  |

## Erreurs et nouvelles tentatives [#errors]

Chaque SDK lève une erreur typée par statut d’erreur (Go et Rust la renvoient). Une clé refusée donne l’erreur 401 du SDK, une permission manquante sa 403. L’erreur porte l’[enveloppe](/developers/conventions/errors#errors) qu’a répondue l’API, avec son `code`, son `message` et son `requestId`. Journalisez l’identifiant de la requête, et citez-le quand vous demandez de l’aide.

Le SDK renvoie ou non la requête selon son type :

| Requête            | Le SDK                                                                                                                                                                                                                      |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET, PUT ou DELETE | La renvoie, avec un délai croissant, quand l’API répond 408, 429 ou 5xx. Les options de chaque requête fixent combien de fois (`maxRetries`, `max_retries`, `option.WithMaxAttempts`, `MaxRetries` : chaque README le dit). |
| POST ou PATCH      | Ne l’envoie jamais deux fois, parce que le premier envoi a pu créer la publication avant que sa réponse ne se perde.                                                                                                        |

Pour renvoyer un POST sans risque, donnez-lui une `Idempotency-Key` ([Idempotence](/developers/conventions/idempotency#idempotency)). L’API répond alors la même publication, et n’en crée pas d’autre.

Une clé peut envoyer {{api-with-fr}} requêtes par minute, ou {{api-without-fr}} pour un compte de facturation sans moyen de paiement ([Limites de débit](/developers/conventions/rate-limits#rate-limits)).

## Pages [#paging]

Les listes qui grandissent sans fin se lisent page par page. Passez `limit` et `cursor`, puis passez le `nextCursor` de la réponse comme `cursor` suivant, jusqu’à ce qu’il vaille `null` ([Pagination](/developers/conventions/paging#paging)). Les listes de l’API partenaire (`/api/partner/workspaces`, `/api/partner/usage`, `/api/partner/overview`) prennent `before` à la place, et répondent `next`.

Les SDK passent les deux tels quels. Aucun n’a d’aide qui lise toutes les pages pour vous, c’est donc à vous d’écrire la boucle :

```ts Node.js
  }
```

## Vérifier un webhook [#webhooks]

Les SDK appellent l’API, mais ne reçoivent pas les [webhooks](/developers/webhooks). Vérifiez chaque livraison avec la bibliothèque [Standard Webhooks](https://www.standardwebhooks.com) de votre langage avant d’agir. [Vérifier une livraison](/developers/webhooks/requests#verify) dit ce qui est signé. En bref :

- Le secret du point de terminaison est `whsec_` suivi de base64. Il n’est affiché qu’une fois, à la création du point de terminaison ([Le secret de signature](/developers/webhooks/requests#secret)).
- Chaque livraison porte `webhook-id`, `webhook-timestamp` et `webhook-signature` ([Ce que Peal envoie](/developers/webhooks/requests#request)).
- Les bibliothèques refusent un horodatage à plus de cinq minutes du moment présent.
- Pendant 24 heures après une rotation, `webhook-signature` contient deux signatures, une par secret. Les bibliothèques acceptent l’une ou l’autre.

Vérifiez le corps tel qu’il est arrivé, octet par octet, avant de l’analyser :

<CodeGroup>

```ts Node.js
// npm install standardwebhooks

// Lève une erreur quand la signature ou l’horodatage est faux.
const event = webhook.verify(rawBody, {
  "webhook-id": request.headers["webhook-id"],
  "webhook-timestamp": request.headers["webhook-timestamp"],
  "webhook-signature": request.headers["webhook-signature"],
});
```

```go Go
// go get github.com/standard-webhooks/standard-webhooks/libraries
import (
	"io"
	"net/http"
	"os"

	standardwebhooks "github.com/standard-webhooks/standard-webhooks/libraries/go"
)

func handle(w http.ResponseWriter, r *http.Request) {
	webhook, err := standardwebhooks.NewWebhook(os.Getenv("PEAL_WEBHOOK_SECRET"))
	if err != nil {
		http.Error(w, "misconfigured", http.StatusInternalServerError)
		return
	}

	// Le corps de la requête tel que reçu.
	rawBody, err := io.ReadAll(r.Body)
	if err != nil {
		http.Error(w, "unreadable", http.StatusBadRequest)
		return
	}

	if err := webhook.Verify(rawBody, r.Header); err != nil {
		http.Error(w, "invalid signature", http.StatusBadRequest)
		return
	}

	w.WriteHeader(http.StatusNoContent)
}
```
