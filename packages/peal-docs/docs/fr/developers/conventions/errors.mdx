Toutes les erreurs de l’API ont la même forme : un client les traite toutes au même endroit. Cette page décrit cette forme, dit que faire de chaque statut, et liste tous les codes.

## Erreurs [#errors]

Chaque erreur est un objet JSON qui porte les quatre mêmes champs, puis ceux qui lui sont propres :

| Champ       | Ce qu’il contient                                                                                                                                                                                       |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `code`      | Le nom de l’erreur pour les programmes, en snake case, comme `post_not_found`. Il ne change jamais une fois publié : c’est sur lui que votre code se décide.                                            |
| `_tag`      | Le même nom, tel que le lisent les clients générés depuis le contrat, comme `PostNotFound`. Il ne change jamais non plus.                                                                               |
| `message`   | Une ou deux phrases en anglais, pour la personne qui lit un journal ou un terminal. Sa formulation peut changer : ne l’analysez jamais.                                                                 |
| `requestId` | L’identifiant de la requête, tel que le donne son en-tête `X-Request-Id`.                                                                                                                               |
| les autres  | Ce que l’erreur dit d’elle-même, comme la référence le liste pour chacune : le statut (`status`) d’une publication, la limite (`limit`) atteinte par un abonnement, les `violations` d’une publication. |

<Callout type="info">
  Deux familles de routes répondent autrement, comme leurs propres clients
  l’attendent : les routes du service de connexion, sous `/api/auth`, et le
  [point d’accès MCP](/developers/mcp), qui répond des erreurs JSON-RPC. Leurs
  réponses portent aussi `X-Request-Id`.
</Callout>

### Que faire d’une erreur [#handling]

| Réponse                       | Ce qu’elle signifie                                                                                                         | Ce que fait un client                                                                                                                                                                      |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 400                           | La requête est fausse.                                                                                                      | La corriger comme le disent `issues` ou `message`. Renvoyée telle quelle, elle échoue de nouveau.                                                                                          |
| 401                           | Le moyen d’authentification ne fonctionne pas.                                                                              | Renouveler le jeton d’accès avec le jeton de renouvellement, ou prendre une clé qui fonctionne.                                                                                            |
| 402 `plan_limit_reached`      | L’abonnement de l’espace de travail n’a plus de place.                                                                      | Prévenir la personne : `planWithRoom` et `billingUrl` disent où aller. Ne pas réessayer.                                                                                                   |
| 402 `usage_allowance_reached` | Un compteur du compte de facturation est épuisé pour le mois.                                                               | Prévenir la personne : `reason` et `billingUrl` disent quoi faire ; sinon attendre `resetsAt`. Ne pas réessayer avant.                                                                     |
| 403                           | Le moyen d’authentification ne le permet pas.                                                                               | Lire `reason`. Ne pas réessayer tant que le scope ou la permission n’est pas accordé.                                                                                                      |
| 404                           | Rien à cet endroit pour cet appelant.                                                                                       | Vérifier les identifiants et l’espace de travail. Ne pas réessayer.                                                                                                                        |
| 409                           | Ce sur quoi porte la requête n’est pas dans un état qui la permet.                                                          | Le relire, puis décider : une publication déjà programmée n’a pas besoin d’une seconde requête.                                                                                            |
| 413, 422                      | Le contenu a été refusé.                                                                                                    | Le corriger comme le disent les champs de l’erreur : `violations`, `channelIds`, `mediaIds`, `reason`.                                                                                     |
| 429 `too_many_requests`       | La clé ou l’application a dépassé sa [limite de débit](/developers/conventions/rate-limits#rate-limits). Rien n’a été fait. | Attendre ce que dit `Retry-After`, puis renvoyer la requête.                                                                                                                               |
| 429, un autre code            | La limite d’une fonction, comme les demandes quotidiennes à l’assistant.                                                    | Attendre ce que dit l’erreur (`resetsAt`), ou un instant pour `media_import_busy`.                                                                                                         |
| 500 `internal_error`          | Le serveur a échoué, et l’a consigné.                                                                                       | Réessayer une lecture. Pour une écriture, relire d’abord ce sur quoi elle porte : elle a pu être appliquée. Ne renvoyer `posts.send` qu’avec la même `Idempotency-Key`. Citer `requestId`. |
| 502, 503                      | Le serveur, ou un service dont il a besoin, ne peut pas répondre pour l’instant.                                            | Réessayer quelques fois, en espaçant de plus en plus les essais, sous la même `Idempotency-Key` là où le point d’accès en accepte une.                                                     |

### Une requête illisible [#invalid-request]

Une requête qui ne correspond pas à ce que son point d’accès attend répond 400 `invalid_request`, et rien n’a été fait.

- `issues` liste ce qui ne va pas, 20 problèmes au plus. Chacun a un chemin (`path`), qui commence par la partie de la requête concernée (`path`, `query`, `headers` ou `body`) et descend jusqu’à la valeur, et un `message`.
- `field` est le chemin du premier problème, séparé par des points.
- La lecture peut s’arrêter au premier problème : corriger ce qui est listé peut en révéler un autre.

```bash
curl -i "https://api.example.com/api/workspaces/$WORKSPACE_ID/media?limit=500" \
  -H "Authorization: Bearer $PEAL_API_KEY"
```

```http
HTTP/1.1 400 Bad Request
Content-Type: application/json
X-Request-Id: 019a7b2e-5c1d-7f3a-9e42-8b6d0c1a2f37
```

```json
{
  "_tag": "InvalidRequest",
  "code": "invalid_request",
  "message": "The request does not match what the endpoint takes: `issues` says what and where. Nothing was done.",
  "requestId": "019a7b2e-5c1d-7f3a-9e42-8b6d0c1a2f37",
  "field": "query.limit",
  "issues": [
    {
      "path": ["query", "limit"],
      "message": "Expected a value between 1 and 100"
    }
  ]
}
```

Une valeur de la bonne forme, mais inutilisable là où elle a été envoyée, comme un curseur venu d’une autre liste, répond 400 `bad_request`.

### Une requête qui n’est pas permise [#forbidden]

Un 403 dit pourquoi dans `reason`, nomme la `permission` que la requête demande quand il en manque une, et le `scope` à demander quand c’est une application OAuth qui ne l’a pas. Son `message` dit comment obtenir ce qui manque.

| `reason`            | Pourquoi                                                                                                                                                                  | Que faire                                                                                                                                                                             |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `missingScope`      | Le membre peut le faire, mais n’a pas accordé à l’application le scope nécessaire (`scope`).                                                                              | Le membre connecte de nouveau l’application et l’autorise ; `peal login` pour la ligne de commande.                                                                                   |
| `missingPermission` | Le rôle du membre, ou la clé d’API, n’a pas la `permission`.                                                                                                              | Un propriétaire ou un administrateur change le rôle, ou crée une clé qui la porte.                                                                                                    |
| `personRequired`    | Seule une personne, dans sa propre session de l’application web, peut le faire.                                                                                           | Rien qu’une clé ou une application puisse faire.                                                                                                                                      |
| `wrongWorkspace`    | La clé ou le jeton appartient à un autre espace de travail.                                                                                                               | Utilisez-le là-bas, ou prenez un moyen d’authentification de cet espace de travail.                                                                                                   |
| `suspended`         | Le compte est suspendu.                                                                                                                                                   | Écrivez à ceux qui gèrent le serveur.                                                                                                                                                 |
| `untrustedOrigin`   | Un navigateur a envoyé le cookie de session depuis un autre site.                                                                                                         | Envoyez plutôt une clé d’API ou un jeton OAuth.                                                                                                                                       |
| `twoStepRequired`   | L’espace de travail exige la validation en deux étapes, et le compte du membre ne l’a pas activée ; ou, pour la console d’administration, le serveur l’exige de l’équipe. | La personne l’active dans les [paramètres de son compte](/guides/workspace/account#two-step) ; le même jeton fonctionne de nouveau. Les clés d’API ne sont jamais refusées pour cela. |

Un jeton auquel il manque un scope reçoit aussi, dans `WWW-Authenticate`, la demande que lisent les clients OAuth :

```bash
curl -i -X POST https://api.example.com/api/workspaces/$WORKSPACE_ID/posts/019a6c3f-1b72-7d3c-8e90-4f5a6b7c8d02/cancel \
  -H "Authorization: Bearer $PEAL_ACCESS_TOKEN"
```

```http
HTTP/1.1 403 Forbidden
Content-Type: application/json
WWW-Authenticate: Bearer error="insufficient_scope", scope="workspace:publish"
X-Request-Id: 019a7b2f-9a04-7b61-8c3d-2e5f7a1b4c68
```

```json
{
  "_tag": "Forbidden",
  "code": "forbidden",
  "message": "This application was not given the scope workspace:publish (schedule and publish posts), which this request takes (permission post:schedule). Its user connects it to Peal again and allows it; for Peal's command line, run peal login again and approve it.",
  "requestId": "019a7b2f-9a04-7b61-8c3d-2e5f7a1b4c68",
  "reason": "missingScope",
  "permission": "post:schedule",
  "scope": "workspace:publish"
}
```

## Codes d’erreur [#error-codes]

Tous les codes que l’API répond, avec le statut qui les accompagne. La référence liste, pour chaque point d’accès, les erreurs qu’il déclare et leurs champs.

- N’importe quel point d’accès peut aussi répondre les erreurs générales : `invalid_request`, `bad_request`, `unauthenticated`, `forbidden`, `not_found`, `method_not_allowed`, `gone`, `payload_too_large`, `internal_error` et `service_unavailable`.
