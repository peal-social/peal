## Pagination [#paging]

Une liste qui peut grandir sans fin se lit page par page, les éléments les plus récents d’abord :

1. Envoyez `limit`, la taille d’une page, dans la requête.
2. Lisez dans la réponse les éléments de la page (`items`) et son `nextCursor`.
3. Passez `nextCursor` en `cursor` pour lire la page suivante, et arrêtez-vous quand il vaut `null`.

Un curseur est une chaîne opaque. Il vaut pour la liste dont il vient, avec les mêmes filtres. Partout ailleurs, il répond 400 `bad_request`.

Chaque liste a sa propre taille de page :

| Liste                                    | Une page contient | Au plus |
| ---------------------------------------- | ----------------- | ------- |
| `GET …/posts/drafts`                     | 20                | 50      |
| `GET …/media`                            | 30                | 100     |
| `GET …/webhooks/{endpointId}/deliveries` | 30                | 100     |
| `GET …/workspace/activity`               | 30                | 100     |

Les chemins qui commencent par `…` sont sous `/api/v1`.

Demandez la première page :

Passez le `nextCursor` ci-dessus pour obtenir la page suivante. Les SDK n’ont pas d’aide qui lise toutes les pages pour vous. Chacun montre donc la boucle :

<CodeGroup>

```ts Node.js
let cursor: string | undefined;

do {
  const page = await peal.workspace.activity.list({ limit: "100", cursor });

  for (const entry of page.items) {
    console.log(entry.operation, entry.status);
  }

  cursor = page.nextCursor ?? undefined;
} while (cursor !== undefined);
```

```python Python
cursor = None

while True:
    page = peal.workspace.activity.list(limit="100", cursor=cursor)

    for entry in page.items:
        print(entry.operation, entry.status)

    cursor = page.next_cursor
    if cursor is None:
        break
```

```go Go
var cursor *string

for {
	page, err := client.Workspace.Activity.List(ctx, &workspace.ListActivityRequest{
		Limit:  peal.String("100"),
		Cursor: cursor,
	})
	if err != nil {
		return err
	}

	for _, entry := range page.Items {
		fmt.Println(entry.Operation)
	}

	if page.NextCursor == nil {
		break
	}
	cursor = page.NextCursor
}
```

```ruby Ruby

  page = peal.workspace.activity.list(**query)

  page.items.each { |entry| puts "#{entry.operation} #{entry.status}" }

  cursor = page.next_cursor
  break if cursor.nil?
end
```

### Les listes qui prennent une plage [#ranges]

Deux listes prennent plutôt une plage, et répondent d’un coup tout ce qu’elle contient :

| Liste                                            | Ce qu’elle répond                                                              | Plage                       | Sinon                |
| ------------------------------------------------ | ------------------------------------------------------------------------------ | --------------------------- | -------------------- |
| `GET …/posts/calendar?from=…&to=…`               | Les publications programmées entre deux instants, `from` compris et `to` exclu | Séparés de 62 jours au plus | `invalid_time_range` |
| `GET …/analytics/summary?from=…&to=…&timeZone=…` | Le résumé des publications parties sur une plage de jours, bornes comprises    | 366 jours au plus           | `invalid_date_range` |

Les listes qu’un espace de travail garde courtes arrivent en entier, sous forme de tableau : ses canaux, ses membres, ses invitations en attente, ses clés d’API et ses points de terminaison de webhook.
