Peal sert le Model Context Protocol (MCP), si bien qu’un assistant IA, ou tout autre client MCP, peut travailler dans un espace de travail pour vous. Il peut lire les publications, les médias, les statistiques, la facturation et les membres de l’espace, et rédiger des brouillons. Il peut programmer et publier des publications quand vous l’y autorisez, et assurer le suivi des publications parties.

Le client se connecte en votre nom, dans un navigateur. Il agit dans le seul espace de travail que vous choisissez, et jamais au-delà de ce que votre rôle permet. Un agent qui tourne sans personne pour le connecter se sert plutôt d’une [clé d’API](#api-key). [Publier depuis un agent IA](/developers/agents) déroule une publication entière.

## Le point d’accès [#endpoint]

Le point d’accès est `/api/mcp`, à l’adresse où vous ouvrez Peal, comme `https://peal.example.com/api/mcp`. Il parle Streamable HTTP, dans les révisions 2026-07-28, 2025-11-25 et 2025-06-18 du protocole.

Lancez `peal mcp`, depuis la [ligne de commande](/developers/cli#mcp), et il affiche le point d’accès et une configuration que la plupart des clients MCP acceptent :

```json
{
  "mcpServers": {
    "peal": {
      "type": "http",
      "url": "https://peal.example.com/api/mcp"
    }
  }
}
```

Donnez au client cette adresse, ou cette configuration, comme sa documentation l’indique pour ajouter un serveur distant en HTTP.

Avant de se connecter, un client peut lire la fiche du point d’accès (server card), à `/api/mcp/server-card`, comme `https://peal.example.com/api/mcp/server-card`. Elle donne l’adresse du point d’accès, les révisions du protocole qu’il parle et l’en-tête qui porte le moyen d’authentification. Elle se lit sans authentification, et depuis des pages de n’importe quelle origine ([Découverte](/developers/conventions/discovery#discovery)).

## Connecter le client [#sign-in]

Peal connecte les clients MCP avec OAuth, donc vous ne donnez aucune clé au client. À sa première requête, Peal lui répond qu’il lui faut un jeton, et lui indique où le demander.

<Steps>
  <Step title="Se connecter">
    Le client s’enregistre auprès de Peal, puis ouvre un navigateur sur la page
    de connexion de Peal. Connectez-vous si ce n’est pas déjà fait.
  </Step>
  <Step title="Choisir un espace de travail">
    Le client n’agit que dans celui-là. Pour l’utiliser dans un autre,
    connectez-le de nouveau et choisissez l’autre.
  </Step>
  <Step title="Vérifier ce qu’il demande">
    Peal montre ce que le client demande, et où il vous renvoie ensuite. Publier
    a sa propre ligne, avec une case que vous pouvez décocher pour ne le laisser
    écrire que des brouillons ([Ce que le client peut faire](#scopes)). Vérifiez
    les deux, puis cliquez sur **Autoriser** ou **Refuser**.
  </Step>
</Steps>

De retour dans le client, ses outils fonctionnent. Peal retient votre réponse pour ce client et cet espace de travail : le connecter de nouveau ne repose pas la question.

<Callout type="warning" title="N’autorisez qu’un client de confiance">
  Peal ne vérifie pas qui a fait un client qui s’est enregistré lui-même, et la
  page de consentement le dit. N’en autorisez un que si vous lui faites
  confiance et avez lancé la connexion vous-même.
</Callout>

La plupart des clients MCP s’enregistrent eux-mêmes avant de se connecter. Un serveur Peal ne l’autorise que si son administrateur l’active (`MCP_DYNAMIC_REGISTRATION`, voir [Auto-hébergement](/self-hosting#mcp)), et `peal mcp` vous prévient quand ce n’est pas le cas.

<Accordion>
<AccordionItem title="Avec la validation en deux étapes">

Quand votre compte a activé la [validation en deux étapes](/guides/workspace/account#two-step), le navigateur demande la seconde étape quand vous vous y connectez, et la connexion se poursuit ensuite. Une connexion faite auparavant n’est pas redemandée.

Un espace de travail peut l’[exiger](/guides/workspace#require-two-step) alors que votre compte ne l’a pas activée. Chaque requête d’un client qui agit pour vous est alors refusée, avec une erreur JSON-RPC et le statut 403. L’erreur dit de l’activer dans les paramètres de votre compte Peal. Une fois activée, la même connexion fonctionne de nouveau.

Un client qui utilise une [clé d’API](#api-key) n’est pas concerné. Aucun outil ne lit ni ne modifie la validation en deux étapes ou l’exigence d’un espace de travail : elles reviennent à une personne, dans un navigateur.

</AccordionItem>
</Accordion>

## Se connecter avec une clé d’API [#api-key]

Un agent qui tourne sur un serveur, sans personne pour le connecter, envoie la [clé d’API](/guides/workspace#api-keys) d’un espace de travail à la place d’un jeton OAuth, dans l’en-tête `Authorization`. Une [clé partenaire](/developers/embedding) envoie aussi un en-tête `Peal-Workspace` ([ci-dessous](#partner-key)). Dans la configuration du client, cela donne :

<CodeGroup>

```json Clé d’API
{
  "mcpServers": {
    "peal": {
      "type": "http",
      "url": "https://peal.example.com/api/mcp",
      "headers": {
        "Authorization": "Bearer ${PEAL_API_KEY}"
      }
    }
  }
}
```

```json Clé partenaire
"headers": {
  "Authorization": "Bearer ${PEAL_PARTNER_KEY}",
  "Peal-Workspace": "<workspace-id>"
}
```

</CodeGroup>

La façon dont un client lit un en-tête dans son environnement dépend du client : voyez sa documentation. Gardez la clé hors des fichiers que vous partagez.

<Callout
  type="warning"
  title="Envoyez la clé dans l’en-tête, jamais dans l’adresse"
>
  Une adresse finit dans des journaux et des historiques, et la clé avec elle.
</Callout>

Une connexion avec une clé fonctionne ainsi :

- Elle agit dans l’espace de travail de la clé, avec les permissions de la clé et sans scope. Une clé sans `post:schedule` écrit tout au plus des brouillons : créez une clé qui ne porte que ce dont l’agent a besoin.
- `whoami` répond la clé dans `apiKey`, avec son identifiant et son nom, jamais la clé elle-même. `user` et le rôle (`role`) de l’espace de travail valent `null`, car une clé n’est personne, et `permissions` liste ce que la clé peut faire.
- L’outil réservé à une personne refuse une clé : `list_members`.
- Ce que fait la clé figure dans le [journal d’activité](/guides/workspace#activity) de l’espace de travail, sous l’identifiant et le nom de la clé.
- Révoquer la clé, sous **Clés d’API** dans les paramètres de l’espace de travail, arrête l’agent aussitôt.

### Avec une clé partenaire [#partner-key]

Une clé partenaire se connecte de la même façon, à l’un des espaces de travail que possède son compte partenaire. La clé les couvre tous, donc le client nomme l’espace de travail à chaque requête, par son identifiant, dans un en-tête `Peal-Workspace` à côté d’`Authorization`.

Sans cet en-tête, le point d’accès répond 400. Pour un espace de travail que le compte partenaire ne possède pas, son espace principal compris, il répond 404. Sinon, les outils agissent dans cet espace de travail avec les permissions de la clé, comme pour une clé d’API.

## Ce que le client peut faire [#scopes]

La page de consentement liste ce que le client demande :

| Permission                                                                                                                                       | Scope               | Ce qu’elle permet                                                                                                                                                                                            |
| ------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Savoir que c’est vous                                                                                                                            | `openid`            | L’identifiant de votre compte                                                                                                                                                                                |
| Voir votre nom et votre photo, voir votre adresse e-mail                                                                                         | `profile`, `email`  | Votre profil                                                                                                                                                                                                 |
| Rester connectée en votre absence, jusqu’à ce que vous la déconnectiez                                                                           | `offline_access`    | Renouveler son accès sans vous                                                                                                                                                                               |
| Lire l’espace de travail : publications, canaux, médias et statistiques                                                                          | `workspace:read`    | Lire, sans rien changer                                                                                                                                                                                      |
| Faire ce que votre rôle permet dans l’espace de travail, comme rédiger des brouillons et gérer les médias, sans rien programmer ni publier       | `workspace:write`   | Tout ce que votre [rôle](/guides/posts#roles) permet, lecture comprise, sauf ce qui fait partir des publications : rien de ce qu’il fait n’atteint une plateforme                                            |
| L’autoriser à programmer et publier des publications sur vos comptes connectés, et à y répondre aux commentaires, où tout le monde peut les voir | `workspace:publish` | Ce que votre rôle permet de ce qui fait partir des publications, et la lecture : programmer, déplacer, publier et republier une publication, la déprogrammer, l’annuler, et confirmer ce qu’elle est devenue |

Publier est une permission à part. La page de consentement la montre sur sa propre ligne, avec une case cochée au départ. Décochez-la, et le client reçoit le reste de ce qu’il a demandé, sans plus. Sans elle, un client qui peut écrire rédige toujours des brouillons, que vous relisez et programmez vous-même. Un client qui ne peut que lire lit toujours.

Un client connecté avant que publier ait sa propre permission n’a que celle d’écrire. Tant que vous ne l’avez pas connecté de nouveau en autorisant la publication, il ne publie rien, et ne déprogramme, ne republie ni ne confirme plus rien. Une connexion garde jusque-là les permissions qu’elle a reçues.

<Callout type="warning" title="Les publicités dépensent de l’argent">
  Un client peut aussi demander `workspace:ads`, pour les
  [publicités](/guides/engage/ads#access). Seule, elle n’ouvre rien. Avec la
  permission d’écrire, le client peut déconnecter des comptes publicitaires et
  mettre en pause ou arrêter des mises en avant. Avec la permission de publier,
  il peut mettre en avant des publications, ce qui dépense de l’argent sur un
  réseau publicitaire, dans la limite du plafond mensuel fixé par un
  propriétaire. Aucun client ne peut activer les dépenses ni changer un plafond.
</Callout>

Aucun client n’invite personne, n’annule d’invitation, ni ne change ou ne retire un membre, quoi que vous lui permettiez : une personne qu’il inviterait aurait ce que vous ne lui avez pas permis, et resterait une fois le client déconnecté. Seule la [ligne de commande](/developers/cli/workspace#members) de Peal le fait, en plus de vous dans l’application web.

Un client qui n’a aucune des trois permissions ci-dessus sur l’espace de travail ne peut rien faire. Son accès dure 15 minutes à la fois, et le client le renouvelle de lui-même. Chaque requête vérifie que vous appartenez toujours à l’espace de travail et n’êtes pas banni.

## Limites [#limits]

Le point d’accès a ces limites :

- Une instance Peal ne sert les clients MCP que si son adresse est en HTTPS, ou sur `localhost` pour le développement. Ailleurs, le point d’accès refuse toutes les requêtes.
- Le point d’accès refuse les requêtes envoyées depuis des pages web (avec un en-tête `Origin`). Connectez un client qui tourne sur votre ordinateur ou sur un serveur.
- Une connexion peut envoyer {{api-with-fr}} requêtes par minute ({{api-without-fr}} pour un compte de facturation sans moyen de paiement), comptées avec celles que la même clé ou la même application envoie à l’API. Au-delà, le point d’accès répond 429 avec un en-tête `Retry-After` ([Limites de débit](/developers/conventions/rate-limits#rate-limits)).
- Chaque réponse porte un en-tête `X-Request-Id`. Citez-le quand vous demandez de l’aide ([Requêtes et réponses](/developers/conventions#requests)).

Pour voir et déconnecter les clients que vous avez autorisés, ouvrez les **Paramètres du compte**, dans l’application web. `peal account apps` les liste depuis la [ligne de commande](/developers/cli/workspace#account). Quitter l’espace de travail arrête tous les clients qui y agissent.
