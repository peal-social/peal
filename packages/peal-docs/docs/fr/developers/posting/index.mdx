Vous pouvez envoyer des publications depuis votre propre code, par l’[API HTTP](/developers), les SDK, la ligne de commande ou MCP. Chaque requête ci-dessous a un exemple dans chaque langage, et la [référence de l’API](/reference) liste tous les champs.

## Avant de commencer [#start]

Tous les points d’accès de cette page se trouvent sous `/api/v1/posts`. Il vous faut une [clé d’API](/guides/workspace#api-keys), de la forme `peal_…`. Elle agit dans son propre espace de travail : aucune requête ne le nomme ([L’espace de travail d’une requête](/developers/conventions#workspace)).

Les exemples lisent la clé dans `$PEAL_API_KEY`. Le premier exemple crée le client, comme le montre [SDK](/developers/sdks#credential), et les suivants le réutilisent : `peal` dans chaque langage sauf Go, où il s’appelle `client`. Les commandes agissent dans l’espace de travail où `peal` est connecté ([Ligne de commande](/developers/cli)).

Les identifiants sont inventés et les réponses abrégées. Une vraie réponse contient toujours la publication entière, telle que la renvoie `GET …/posts/{postId}`.

Chaque requête demande ces permissions :

| Requête                        | Ce qu’elle fait                                           | Demande                                      |
| ------------------------------ | --------------------------------------------------------- | -------------------------------------------- |
| `POST …/posts/validate`        | Vérifie une publication, sans rien créer                  | `post:read`, `channel:read`                  |
| `POST …/posts`                 | Crée une publication et l’envoie, maintenant ou plus tard | `post:schedule`, `channel:read`              |
| `GET …/posts/{postId}/outcome` | Attend qu’une publication soit partie                     | `post:read`                                  |
| `POST …/posts/bulk`            | Crée et envoie jusqu’à 50 publications                    | `post:schedule`, `channel:read`              |
| `POST …/posts/import`          | Crée et envoie les publications d’un fichier CSV          | `post:schedule`, `post:read`, `channel:read` |
| `GET …/posts`                  | Liste les publications de l’espace de travail, filtrées   | `post:read`, `channel:read`                  |

Une publication qui montre des médias demande aussi `media:read`. Un jeton d’accès OAuth a besoin du scope `workspace:publish` pour `create`, `bulk` et `import` ([Ce que permet chaque permission](/developers/agents#scopes)).

<Callout
  type="warning"
  title="Peal ne peut pas reprendre une publication une fois partie"
>
  Ce que publient `create`, `bulk` et `import` atteint le public des
  plateformes, et vous ne pouvez plus le reprendre depuis Peal une fois parti.
  Avant son heure, vous pouvez encore annuler ou déprogrammer une publication.
</Callout>

## Vérifier une publication sans la créer [#validate]

`POST …/posts/validate` prend le même corps que `create`, ou celui d’un brouillon, qui n’a pas de `when`. Il n’écrit rien. La réponse est 200, que la publication puisse passer ou non, avec `valid` et toutes les raisons qui la feraient refuser, d’un coup.

<CodeGroup>

```ts Node.js
import { PealClient } from "@peal-social/sdk";

const peal = new PealClient({ token: process.env.PEAL_API_KEY });

const check = await peal.posts.validate({
  channelIds: ["0190f3a0-0000-7000-8000-00000000c001"],
  content: {
    text: "Our spring catalogue is out. Read it at https://example.com/spring #spring",
    media: [],
    overrides: [],
  },
  when: { _tag: "at", at: "2026-11-16T08:00:00Z", timeZone: "Europe/Paris" },
});
```

La réponse contient ces champs :

| Champ             | Ce qu’il contient                                                                                                                                                                                                                |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `valid`           | Vrai quand rien de ce qui suit ne refuse la publication                                                                                                                                                                          |
| `channels`        | Une entrée pour chaque canal de l’espace de travail que nomme la publication, dans l’ordre où vous les donnez                                                                                                                    |
| `violations`      | Ce qui ne va pas quel que soit le canal : aucun canal, ou un texte ou des options pour un canal où la publication ne va pas                                                                                                      |
| `unknownChannels` | Les canaux qu’elle nomme et qui ne sont pas à l’espace de travail                                                                                                                                                                |
| `unknownMedia`    | Les médias qu’elle montre et qui ne sont pas à l’espace de travail, ou pas encore prêts                                                                                                                                          |
| `schedule`        | `ok`, `inPast` (plus d’une minute dans le passé) ou `invalidTimeZone` (pas un fuseau IANA). Null sans `when`.                                                                                                                    |
| `planLimit`       | La limite de l’abonnement que la publication dépasserait, telle que la décrit `PlanLimitReached`. Null quand l’abonnement a de la place, sur une instance qui ne facture pas, ou sans `when`.                                    |
| `awaitsApproval`  | Si la publication, envoyée telle quelle, attendrait une [approbation](/guides/posts/review) avant d’être programmée. Elle serait quand même créée, avec le statut `awaitingApproval`. False sans `when`.                         |
| `duplicates`      | Les canaux qui reçoivent déjà le même contenu par une autre publication proche de son heure, chacun avec cette publication ([Publications en double](#duplicates)). Vide sans `when`, ou quand la requête autorise les doublons. |

`awaitsApproval` ne refuse rien. Il vous dit ce que l’espace de travail demande à cet appelant.

Chaque entrée de `channels` contient :

| Champ                                      | Ce qu’il contient                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `text`                                     | Le texte que reçoit le canal : le sien, ou celui de la publication                                                                                                                                                                                                                                                                                                                            |
| `textCounts`                               | La longueur de ce texte face à chacune des limites de la plateforme, comptée comme la plateforme compte. Bluesky en a deux, en graphèmes et en octets.                                                                                                                                                                                                                                        |
| `hashtags`, `mentions`, `links` et `media` | Combien la publication en contient (`count`) et le maximum que prend la plateforme (`maximum`, null quand Peal ne connaît pas de limite). `links` compte les liens différents. `media` compte ce que reçoit le canal : ses propres médias quand son entrée lui en donne ([Des médias propres sur un canal](#channel-media)), sinon ceux de la publication.                                    |
| `parts`                                    | Les parties qui suivent la première d’un [fil](/guides/posts#threads), dans l’ordre, chacune avec son rang (`part`, à partir de 1), son texte (`text`) sur le canal et les mêmes décomptes. Vide pour une publication seule. Une plateforme qui ne prend que des publications seules les liste quand même, et les refuse avec `tooManyParts`.                                                 |
| `violations`                               | Chaque règle de la plateforme que la publication enfreint, dans n’importe quelle partie (texte, formats, tailles, nombre et durées des médias, options), plus celles du compte quand sa plateforme les donne. Une violation qui porte sur une partie suivante la désigne par `part`. Elles se lisent comme dans `PostContentInvalid` ([Comment lire les refus](/developers/agents#refusals)). |

Une publication qui serait refusée reçoit aussi un 200, avec `valid` à faux :

Sans `when`, la requête est vérifiée comme un brouillon : ni l’heure, ni la place dans l’abonnement, ni les doublons ne sont vérifiés.

<Callout
  type="info"
  title="Une publication valide maintenant peut encore être refusée plus tard"
>
  C’est le cas si un canal est déconnecté ou si le mois de l’abonnement se
  remplit entre-temps.
</Callout>

## Publier maintenant et attendre le résultat [#wait]

`POST …/posts` répond dès que la publication est créée, pendant qu’elle se publie encore. Ajoutez `wait`, un nombre de secondes de 0 à 60, et une publication qui part maintenant reçoit sa réponse une fois que chaque canal a son résultat. Avec l’en-tête `Idempotency-Key`, vous pouvez renvoyer la requête sans risque si la réponse se perd ([Idempotence](/developers/conventions/idempotency#idempotency)).

<CodeGroup>

```ts Node.js
const post = await peal.posts.create({
  wait: "30",
  "idempotency-key": "5f0c2b7e-3d1a-4e58-9a6b-2c4d8e1f7a90",
  channelIds: [
    "0190f3a0-0000-7000-8000-00000000c001",
    "0190f3a0-0000-7000-8000-00000000c002",
  ],
  content: {
    text: "Our spring catalogue is out. Read it at https://example.com/spring",
    media: [],
    overrides: [],
  },
  when: { _tag: "now" },
});
```

La réponse est 201 dans les deux cas, puisque la publication a été créée. Son contenu dépend de l’attente :

- Quand chaque canal termine à temps, le `status` de la publication est `finished`, avec son `outcome`. Chaque cible est `published`, avec son `permalink`, ou `failed`, avec sa `failureReason`.
- Quand le temps s’écoule avant, vous recevez la publication dans son état du moment, avec des cibles encore `pending` ou `publishing`. Elle continue de se publier.

Un [fil](/guides/posts#threads) a son résultat sur un canal quand toutes ses parties y sont parties, ou que l’une a échoué. Entre deux parties, sa cible reste `publishing`, et `parts.live` liste les parties déjà en ligne. Si le fil attend plus longtemps entre deux parties que `wait`, le temps s’écoule avant.

### Attendre la suite [#outcome]

## Publications en double [#duplicates]

Peal refuse une publication quand une autre publication de l’espace de travail envoie déjà le même contenu à l’un de ses canaux, à moins de 23 heures de son heure. La requête répond 409 `DuplicatePost`, et rien n’est créé :

```json
{
  "_tag": "DuplicatePost",
  "duplicates": [
    {
      "channelId": "0190f3a0-0000-7000-8000-00000000c001",
      "postId": "0190f3a0-0000-7000-8000-00000000b001"
    }
  ]
}
```

`duplicates` nomme chaque canal qui reçoit déjà le contenu, avec la première publication qui l’y envoie dans cet intervalle. La vérification suit ces règles :

| Règle              | Détail                                                                                                                                                                                                                                           |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Le même contenu    | Le texte que reçoit le canal, et les mêmes médias dans le même ordre.                                                                                                                                                                            |
| 23 heures          | La journée la plus courte d’un fuseau horaire, si bien qu’une publication qui se répète chaque jour à la même heure locale n’est jamais refusée.                                                                                                 |
| Ce qui compte      | Les publications qui vont partir ou sont parties, y compris celles qui attendent une approbation, puisqu’elles partent une fois approuvées. Les brouillons, les publications annulées et un canal où la publication a échoué ne comptent pas.    |
| Ce qui est vérifié | `create`, chaque élément de `bulk`, chaque ligne d’`import`, les outils MCP `create_post` et `create_posts`, et `peal post`. Programmer un brouillon existant, déplacer une publication et republier là où elle a échoué ne sont jamais refusés. |
| Quand c’est voulu  | Renvoyez la requête avec `allowDuplicate: true` sur la publication ou l’élément de `bulk`, ou avec `allow_duplicate` à `true` sur la ligne du CSV.                                                                                               |

`validate` vous le dit à l’avance, dans `duplicates`.

<Callout
  type="info"
  title="Cette vérification est distincte des clés d’idempotence"
>
  Avec une clé, vous pouvez renvoyer une même requête sans risque. Le refus des
  doublons rattrape la même publication demandée deux fois.
</Callout>

## Des médias propres sur un canal [#channel-media]

Le texte d’une publication sur un canal, une entrée de `content.overrides` ou des `overrides` d’une partie, peut aussi donner à ce canal ses propres images et vidéos, dans `media`. Le canal les montre alors à la place de celles de la publication :

| `media` sur une entrée | Ce que montre le canal                                                                                            |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Absent                 | Les images et vidéos de la publication. Peal ne renvoie `media` que sur une entrée qui en donne.                  |
| Une liste vide         | Aucune.                                                                                                           |
| Une liste              | Celles-là, dans l’ordre, chacune avec son texte alternatif : 20 au plus, des médias prêts de l’espace de travail. |

Une entrée a toujours un `text`, qui ne peut pas être vide. Pour donner à un canal ses propres médias sans rien d’autre, reprenez-y le texte de la publication. Ce texte appartient alors au canal : quand vous changez le texte de la publication, changez-le là aussi (l’application web le fait pour vous).

```json
{
  "text": "Five pictures of the spring catalogue",
  "media": [
    {
      "mediaId": "0190f3a0-0000-7000-8000-00000000f001",
      "altText": "The cover"
    },
    { "mediaId": "0190f3a0-0000-7000-8000-00000000f002", "altText": "Page two" }
  ],
  "overrides": [
    {
      "channelId": "0190f3a0-0000-7000-8000-00000000c001",
      "text": "Five pictures of the spring catalogue",
      "media": [
        {
          "mediaId": "0190f3a0-0000-7000-8000-00000000f002",
          "altText": "Page two"
        }
      ]
    }
  ]
}
```

Des médias propres changent quelques autres règles :

- Chaque canal est vérifié sur les médias qu’il reçoit, par `validate` (son nombre de `media` et ses `violations`) et quand la publication est programmée.
- La [vérification des doublons](#duplicates) compare ce que reçoit chaque canal.
- Une approbation couvre les médias de chaque canal. Changer les médias propres d’un canal après l’approbation de la publication en redemande une.
- Tant qu’une publication programmée montre un fichier sur un canal, vous ne pouvez pas le supprimer de la médiathèque. Un brouillon ne le retient pas, sur aucun canal.

## Retirer un canal d’une publication programmée [#remove-target]

`DELETE …/posts/{postId}/targets/{targetId}` retire un canal d’une publication qui attend son heure, programmée ou en attente d’approbation. La publication part à son heure sur ses autres canaux, et jamais sur celui-ci. La cible devient `cancelled`, avec `"dropped": true`. La publication garde son heure et son créneau de file d’attente, et une fois partie, son `outcome` laisse ce canal de côté. La requête renvoie la publication.

La requête peut être refusée avec ces erreurs :

| Statut | Code                     | Quand                                                                                                                          |
| ------ | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| 409    | `last_target_left`       | Le canal est le dernier sur lequel la publication part encore. Annulez plutôt la publication (`POST …/posts/{postId}/cancel`). |
| 409    | `post_status_conflict`   | La publication est en cours d’envoi ou terminée, ou c’est un brouillon, dont les canaux se changent par une mise à jour.       |
| 409    | `target_status_conflict` | Le canal a été annulé avec sa publication.                                                                                     |

Un canal déjà retiré renvoie la publication telle qu’elle est. Vous pouvez donc renvoyer la requête sans risque après une réponse perdue.

Retirer un canal compte comme une modification de la publication :

- Là où vos publications demandent une [approbation](/guides/posts/review), l’approbation ne la couvre plus. La réponse porte `awaitingApproval`, et la publication attend une nouvelle approbation. Une publication déjà en attente d’approbation garde sa demande, qui couvre désormais la publication telle qu’elle est.
- Les webhooks reçoivent un [`post.cancelled`](/developers/webhooks/events/posts#post-cancelled) qui nomme ce seul canal, avec `scope` `target`.
- Une publication repassée en brouillon (`unschedule`, des changements demandés, ou une approbation après son heure) garde les canaux qu’elle avait encore. Le canal retiré part avec sa cible et ses entrées d’`overrides` dans chaque partie. Si vous le nommez de nouveau dans `channelIds`, il reçoit une nouvelle cible, en attente.

Il faut post:schedule, ou, sur une publication en attente d’approbation, le droit de demander que des publications partent. Un client OAuth a besoin du scope `workspace:publish`.

## Sondages et premiers commentaires [#polls]

`content.poll` ajoute un sondage à la première partie de la publication, dont le texte est la question. Il a des `choices` (2 à 4), une `durationMinutes`, et `multipleChoice` (faux quand il est omis). Peal ne le renvoie que sur une publication qui en a un. Envoyez `null`, ou omettez-le, pour aucun.

Les capacités d’une plateforme décrivent son `poll` : le nombre de choix, leur `choiceLimit`, `durationMinutes` (`null` là où la plateforme décide de la durée) et `multipleChoice`. Là où elles n’en décrivent pas, une publication avec un sondage est refusée avec `pollNotSupported`. Chaque limite dépassée a sa propre violation : `pollChoiceCount`, `pollChoiceLength`, `pollDurationOutOfRange`, `pollMultipleChoice` ou `pollWithMedia`. Un choix répété est `pollChoiceRepeated`, et Peal retire les espaces autour de chaque choix.

Un premier commentaire est l’unique partie après la première (`content.followUps`), sur les plateformes dont les capacités donnent des `followUps` de type `comment`. C’est du texte seul, dans les `commentTextLimits`. Les capacités ne le proposent que là où le serveur lit les commentaires de cette plateforme, si bien qu’un canal connecté avant est refusé avec `partsNeedReconnect`. Ses capacités le disent à l’avance, dans `account.restrictions`. Certaines plateformes ajoutent leurs propres règles :

- Sur une page LinkedIn, `commentNeeds` dit que l’administrateur de la page doit l’avoir connectée.
- Une vidéo YouTube conçue pour les enfants ne prend pas de commentaire (`commentsTurnedOff`).

Un commentaire peut échouer après la mise en ligne de la publication. Celle-ci est alors `partiallyPublished`, et sa cible compte toujours comme en ligne pour les statistiques, la boîte de réception et les publicités. Une republication envoie le commentaire seul. `POST …/posts/{postId}/targets/{targetId}/leave-out-rest` publie la cible comme une publication sans lui (`partsLeftOut`). Le [guide des publications](/guides/posts#first-comment) explique comment une réponse perdue est tranchée.
