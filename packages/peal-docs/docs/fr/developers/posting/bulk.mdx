Vous pouvez envoyer jusqu’à 50 publications en une requête, ou en importer jusqu’à 100 depuis un fichier CSV, par l’API, les SDK ou la ligne de commande. Les exemples créent le client comme l’explique [Publier par l’API](/developers/posting#start).

## Envoyer plusieurs publications en une requête [#bulk]

`POST …/posts/bulk` crée et envoie jusqu’à 50 publications, chacune comme le ferait `create`. Chaque élément est une publication, avec ses propres canaux, son contenu, ses options et son heure. Le même contenu à deux heures fait donc deux éléments, tout comme une publication qui part à une heure différente sur chaque canal.

Peal traite les éléments dans l’ordre, un à la fois, et chacun pour lui-même. Un élément refusé n’empêche pas les autres d’être créés, et rien n’est défait.

La réponse est 200 dès que Peal a pu lire la requête, même s’il a refusé tous les éléments. `items` donne un résultat par élément, repéré par sa place dans la requête (`index`, à partir de 0) :

- `created`, avec sa publication.
- `refused`, avec ce que `create` aurait répondu pour cet élément seul, sous forme de données : les violations de son contenu, des canaux ou médias inconnus, une heure passée, la limite de l’abonnement ou un doublon.

Une requête que Peal ne peut pas lire du tout (mal formée, sans élément, ou avec plus de 50) répond 400 et ne crée rien.

Les limites de l’abonnement valent pour toute la requête. Une fois le mois plein, les éléments restants sont refusés. Chaque élément est aussi comparé aux publications créées avant lui, éléments précédents de la requête compris, pour le même contenu sur le même canal ([Publications en double](/developers/posting#duplicates)).

### La renvoyer sans risque [#bulk-idempotency]

Avec un en-tête `Idempotency-Key`, vous pouvez renvoyer toute la requête sans risque pendant 24 heures. Peal garde chaque élément sous la clé et sa place :

- La même requête renvoyée répond les publications qu’elle a créées, avec `replayed` à vrai. Elle crée aussi les éléments qui ne l’avaient pas été la première fois, s’ils peuvent l’être désormais.
- Un élément modifié sous la même clé est refusé avec `IdempotencyKeyReused`.
- Un élément peut porter sa propre `idempotencyKey`, qui remplace alors celle de l’en-tête pour lui.

## Importer des publications depuis un fichier CSV [#import]

`POST …/posts/import` crée et envoie les publications que liste un fichier CSV, une par ligne. Dans l’application web, [Importer depuis un fichier](/guides/posts/drafts#import-screen) vérifie un fichier et l’importe par ce point d’accès.

La première ligne du fichier nomme les colonnes, dans n’importe quel ordre :

| Colonne           | Obligatoire | Ce qu’elle contient                                                                                                                                               |
| ----------------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `text`            | oui         | Le texte de la publication                                                                                                                                        |
| `channels`        | oui         | Des identifiants de canaux, séparés par des espaces, des virgules ou des points-virgules                                                                          |
| `at`              | oui         | `now`, un instant avec son décalage comme `2026-11-20T09:00:00Z`, ou une heure locale sans décalage comme `2026-11-20 10:00`, lue dans le `time_zone` de la ligne |
| `time_zone`       | non         | Un fuseau IANA, comme `Europe/Paris`. UTC s’il est absent.                                                                                                        |
| `media`           | non         | Des identifiants de médias prêts de l’espace de travail                                                                                                           |
| `allow_duplicate` | non         | `true` ou `false` ([Publications en double](/developers/posting#duplicates))                                                                                      |
| `idempotency_key` | non         | La clé d’idempotence propre à la ligne                                                                                                                            |

Une ligne est une publication seule, avec un seul texte pour tous ses canaux. Un [fil](/guides/posts#threads), un texte différent sur un canal ou les options d’une plateforme ne tiennent pas dans une cellule : envoyez-les par `create` ou `bulk`. Un fichier qui nomme une autre colonne est refusé en entier.

### Écrire le fichier [#csv]

Les cellules suivent strictement la RFC 4180, si bien qu’aucun texte n’est jamais coupé. Une cellule qui contient une virgule, un guillemet ou un saut de ligne s’écrit entre guillemets doubles, et un guillemet à l’intérieur est doublé. Une ligne se termine après sa dernière cellule, sans virgule finale. Un fichier contient au plus 100 lignes sous la première, et 1 000 000 de caractères.

```csv title="posts.csv"
text,channels,at,time_zone,media
Our spring catalogue is out.,0190f3a0-0000-7000-8000-00000000c001 0190f3a0-0000-7000-8000-00000000c002,2026-11-20 10:00,Europe/Paris,0190f3a0-0000-7000-8000-00000000a001
"Last days: the ""spring"" prices end on Sunday, at midnight.",0190f3a0-0000-7000-8000-00000000c001,2026-11-27T09:00:00Z,,
```

```json
{
  "created": 0,
  "dryRun": true,
  "rows": [
    { "_tag": "valid", "row": 1 },
    { "_tag": "valid", "row": 2 }
  ]
}
```

Peal vérifie d’abord chaque ligne, comme `validate` vérifie une publication, puis le fichier dans son ensemble :

- Une ligne à laquelle une ligne précédente ne laisse plus de place dans son mois est refusée avec `PlanLimitReached`.
- Une ligne qui répète une ligne précédente sur le même canal, à moins de 23 heures d’elle, est refusée avec `DuplicatePost`. Son `message` nomme cette ligne, puisqu’il n’y a pas encore de publication à nommer.
- Une ligne qui reprend la `idempotency_key` d’une ligne précédente avec une autre publication est refusée avec `IdempotencyKeyReused`.

<Callout type="info" title="Une ligne invalide arrête tout l’import">
  Peal ne crée rien tant que toutes les lignes ne sont pas valides. `dryRun :
  true` s’arrête là même quand elles le sont toutes. Sinon, Peal crée ensuite
  les lignes dans l’ordre, comme `bulk` crée ses éléments.
</Callout>

### Lire le résultat [#import-result]

`rows` contient un résultat par ligne, repérée par sa place sous la première ligne, à partir de 1. Les lignes vides ne sont pas des lignes, et ne sont pas comptées. Chaque résultat porte l’une de ces étiquettes :

| `_tag`       | Signification                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `created`    | La publication de la ligne a été créée. `post` la contient, et `replayed` dit si sa clé d’idempotence a répondu une publication créée avant.                                                                                                                                                                                                                                                                     |
| `valid`      | La ligne a été vérifiée sans être créée, lors d’un essai à blanc ou parce qu’une autre ligne a empêché l’import du fichier.                                                                                                                                                                                                                                                                                      |
| `refused`    | `refusal` contient ce que `create` aurait répondu pour elle. Une ligne qui avait passé la vérification est aussi refusée quand quelque chose a changé depuis, ou quand elle répète une ligne précédente.                                                                                                                                                                                                         |
| `unreadable` | `problems` nomme les cellules en cause : chaque `column`, `missing` quand la ligne en a besoin, ou `invalid` pour ce qu’elle contient. Une ligne avec plus ou moins de cellules que n’en nomme la première ligne n’est pas lue du tout, et `cells` dit combien étaient attendues (`expected`) et trouvées (`found`). Une virgule dans un texte qui n’est pas entre guillemets doubles suffit à en provoquer une. |

```json
{
  "created": 0,
  "dryRun": false,
  "rows": [
    { "_tag": "valid", "row": 1 },
    {
      "_tag": "unreadable",
      "row": 2,
      "problems": [{ "column": "at", "problem": "invalid" }]
    }
  ]
}
```

La réponse est 200 dès que Peal a pu lire le fichier. Un fichier qu’il ne peut pas lire du tout répond 422 `ImportUnreadable`, et rien n’est créé. `problem` dit pourquoi, et `column` nomme la colonne quand le problème en concerne une :

| `problem`           | Le fichier                                                                                                    |
| ------------------- | ------------------------------------------------------------------------------------------------------------- |
| `empty`             | est vide                                                                                                      |
| `unterminatedQuote` | a une cellule entre guillemets qui ne se termine jamais                                                       |
| `strayQuote`        | a un guillemet double dans une cellule qui n’est pas entre guillemets, ou du texte après un guillemet fermant |
| `unknownColumn`     | nomme une colonne que Peal ne connaît pas                                                                     |
| `repeatedColumn`    | nomme deux fois la même colonne                                                                               |
| `missingColumn`     | n’a pas une colonne dont il a besoin                                                                          |
| `tooManyRows`       | a plus de lignes qu’un import n’en prend                                                                      |

```json
{ "_tag": "ImportUnreadable", "problem": "missingColumn", "column": "at" }
```

Un en-tête `Idempotency-Key` fonctionne comme sur `bulk`, ligne par ligne.
