Vous pouvez retrouver les publications qui ont échoué la semaine dernière, tout ce qui reste programmé sur un canal, ou les publications créées par une clé. Les exemples créent le client comme l’explique [Publier par l’API](/developers/posting#start).

## Filtrer les publications [#search]

`GET …/posts/search` liste les publications de l’espace de travail, quel que soit leur état, une page à la fois. Une page contient 20 publications sauf si `limit` en décide autrement, et 100 au plus. Quand vous donnez plusieurs filtres, une publication doit les satisfaire tous. L’[outil MCP](/developers/mcp/tools#tools) `list_posts` prend les mêmes filtres, et `peal posts list` liste les mêmes publications ([Ligne de commande](/developers/cli/posts#posts)).

La requête prend ces paramètres :

| Paramètre     | Ce qu’il garde                                                                                                                                                                                    |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `status`      | `draft`, `awaitingApproval` (en attente d’une [approbation](/guides/posts/review), son heure gardée), `scheduled`, `publishing`, `finished` ou `cancelled`                                        |
| `outcome`     | Comment une publication terminée a fini : `published`, `partiallyPublished`, `unconfirmed`, `failed` ou `cancelled`                                                                               |
| `channelId`   | Les publications qui ont une cible sur ce canal                                                                                                                                                   |
| `platform`    | Les publications qui ont une cible sur un canal connecté de cette plateforme                                                                                                                      |
| `tagId`       | Les publications classées sous cette étiquette                                                                                                                                                    |
| `queueId`     | Les publications placées par cette file d’attente ([Files d’attente](/developers/posting/queues#queues))                                                                                          |
| `recyclingId` | Les publications créées par cette règle de répétition ([Répéter une publication](/developers/posting/queues#recycling))                                                                           |
| `removed`     | `true` : les publications que Peal a supprimées de la plateforme d’au moins un canal. `false` : celles supprimées d’aucune ([Dépublier une publication](/developers/posting/published#unpublish)) |
| `from`, `to`  | Les publications programmées de `from` (compris) à `to` (exclu). L’un comme l’autre écarte les publications sans heure.                                                                           |
| `createdVia`  | `web`, `apiKey` ou `application`                                                                                                                                                                  |
| `authorId`    | Les publications créées par cet utilisateur                                                                                                                                                       |
| `sort`        | `createdDesc` (par défaut) ou `createdAsc`, par date de création. `scheduledDesc` ou `scheduledAsc`, par instant programmé, qui ne listent que les publications avec une heure                    |
| `limit`       | Le nombre de publications par page, de 1 à 100                                                                                                                                                    |
| `cursor`      | Le `nextCursor` de la page précédente                                                                                                                                                             |

Cette requête liste les publications Bluesky en échec, la plus récemment programmée en premier :

```ts Node.js
import { PealClient } from "peal-sdk";

const peal = new PealClient({ token: process.env.PEAL_API_KEY });

const page = await peal.posts.search({
  status: "finished",
  outcome: "failed",
  platform: "bluesky",
  sort: "scheduledDesc",
  limit: "50",
});
```

Chaque publication arrive en entier, avec ses cibles, leur statut, leur adresse et la raison de leur échec. `channels` donne la plateforme de chaque canal de la page encore connecté, pour que vous puissiez nommer chaque cible sans autre requête.

## Lire la page suivante [#next-page]

Passez `nextCursor` dans `cursor`, avec les mêmes filtres et le même tri. Il est null sur la dernière page.

Un curseur marque l’endroit où sa page s’est arrêtée. Les publications créées, déplacées ou supprimées entre-temps ne font donc jamais répéter ni sauter une publication d’une page à l’autre. Un curseur d’un autre tri, ou qu’aucune page n’a renvoyé, répond 400.

<Callout
  type="info"
  title="Un calendrier peut lire une période entière en une requête"
>
  `GET …/posts?from=…&to=…` existe toujours. Il liste en une seule réponse les
  publications programmées entre deux instants, séparés de 62 jours au plus, par
  instant programmé. Les brouillons n’en font pas partie.
</Callout>
