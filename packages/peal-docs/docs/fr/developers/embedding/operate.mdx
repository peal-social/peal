Une fois qu’un client a un espace de travail et un canal connecté ([Intégrer Peal](/developers/embedding)), votre serveur le gère avec votre clé partenaire.

## Publier pour eux [#post]

Dans l’espace de travail d’un client, votre clé appelle les mêmes points d’accès que n’importe quel autre client : [médias](/guides/media), [publications](/guides/posts) et [statistiques](/guides/engage/analytics). Une clé partenaire n’appartient à aucun espace de travail : chaque requête nomme donc celui du client dans l’en-tête `Peal-Workspace`. Dans les SDK, c’est l’option `workspace` du client : créez un client par espace de travail de client. Les appels propres à l’API partenaire, dans les sections suivantes (`partner`, `partner.customerUsage`), ne nomment aucun espace de travail : ils passent par un client créé sans : `peal` dans ces exemples, `client` en Go.

Cet appel publie une publication en une fois, à un instant donné :

<CodeGroup>

```ts Node.js
import { PealClient } from "peal-sdk";

// Le client de l’API partenaire, qui ne nomme aucun espace de travail.
const peal = new PealClient({
  token: process.env.PEAL_PARTNER_KEY,
  baseUrl: "https://api.example.com",
});

// L’espace de travail de votre client, et l’un de ses canaux.
const workspaceId = "7b1f6c1e-2d4a-4f0b-9c3e-5a8d2e6f1b90";
const channelId = "019a6f40-11aa-7c3d-8e21-9f0b6a5d4c33";

// Un client qui agit dans cet espace de travail : une clé partenaire n’appartient à aucun.
const customer = new PealClient({
  token: process.env.PEAL_PARTNER_KEY,
  baseUrl: "https://api.example.com",
  workspace: workspaceId,
});

const post = await customer.posts.create({
  "idempotency-key": "campaign-881-cus_42",
  channelIds: [channelId],
  content: { text: "Fresh bread at 7.", media: [], overrides: [] },
  when: { _tag: "at", at: "2026-11-12T06:00:00Z", timeZone: "Europe/Paris" },
});
```

## Apprendre ce qui s’est passé [#webhooks]

Ajoutez un point d’accès à votre espace de travail principal avec `scope: "partner"`. Il reçoit les événements de chaque espace de travail que possède votre compte partenaire, et ceux de votre espace principal.

Une clé partenaire n’agit pas dans votre espace de travail principal. Créez donc le point d’accès dans l’application web, connecté, sous **Paramètres**, puis **Webhooks**, ou avec une [clé d’API](/guides/workspace#api-keys) de l’espace principal qui détient `webhook:manage` :

<CodeGroup>

```ts Node.js
// La clé d’API de votre espace de travail principal, pas la clé partenaire.
const home = new PealClient({
  token: process.env.HOME_API_KEY,
  baseUrl: "https://api.example.com",
});

const { endpoint, secret } = await home.webhooks.create({
  url: "https://hooks.example.com/peal",
  eventTypes: [
    "channel.connected",
    "channel.reconnect_needed",
    "post.published",
    "post.failed",
    "post.unconfirmed",
  ],
  scope: "partner",
});
```

La réponse contient le secret de signature du point d’accès, affiché cette seule fois. Un point d’accès avec `scope: "partner"` dans un espace de travail sans compte partenaire reçoit 404 `PartnerNotFound`.

Chaque contenu nomme son espace de travail deux fois. `data.workspaceId` est l’identifiant de Peal, et `workspaceExternalId` le vôtre, tel qu’il était au moment de l’événement (null si vous n’en avez pas donné) :

```json
{
  "id": "019a6f40-2f6b-7a1c-9d2e-5b4c3a2f1e07",
  "type": "channel.connected",
  "version": 1,
  "timestamp": "2026-11-10T09:14:02.000Z",
  "workspaceExternalId": "cus_42",
  "data": {
    "workspaceId": "7b1f6c1e-2d4a-4f0b-9c3e-5a8d2e6f1b90",
    "channelId": "019a6f40-11aa-7c3d-8e21-9f0b6a5d4c33",
    "platform": "linkedin",
    "reconnected": false
  }
}
```

[Webhooks](/developers/webhooks) explique comment les envois sont signés, vérifiés, réessayés et journalisés. Un point d’accès dans l’espace de travail d’un client, avec la portée par défaut, ne reçoit que cet espace-là.

Quelques événements et réglages servent surtout quand vous intégrez Peal :

- [`post.finished`](/developers/webhooks/events/posts#post-finished) arrive quand chaque canal d’une publication a son résultat, avec celui de chacun. Abonnez-vous-y pour marquer une seule fois la publication d’un client comme terminée dans votre produit.
- [`channel.expiring`](/developers/webhooks/events/channels#channel-expiring) vous prévient, une semaine à l’avance au plus, que la connexion d’un canal ne pourra pas être renouvelée. Envoyez un [lien de connexion](/developers/embedding#reconnect) à votre client avant qu’elle n’expire.
- `headers` donne au point d’accès des [en-têtes à lui](/developers/webhooks#headers), pour un récepteur derrière une passerelle qui demande un jeton. Leurs valeurs sont en écriture seule.

### Tenir la préproduction à part avec un filtre d’espaces de travail [#webhooks-staging]

Donnez à chaque environnement son propre point d’accès partenaire, et listez dans `workspaceIds` (200 au plus) les espaces de travail qu’il doit entendre. Votre point d’accès de préproduction reçoit alors vos clients de test, tandis que celui de production, sans liste, reçoit tous les espaces. Votre espace de travail principal n’est entendu que s’il est listé.

Quand vous ajoutez des clients de test, changez la liste avec `PATCH …/webhooks/{endpointId}`.

Le [journal de tous les points d’accès](/developers/webhooks/delivery#log) de votre espace de travail principal contient les envois de chaque point d’accès, chacun avec son espace de travail et votre identifiant pour lui. Vous pouvez y renvoyer ensemble ceux qui ont échoué.

```json
      "externalId": "cus_42",
      "name": "Garage Dupont",

        "scheduledNext7Days": 4,
```

Chaque chiffre compte une chose, et la clé a besoin d’une permission pour le lire :

| Chiffre                      | Ce qu’il compte                                                                                                          | Ouvert par        |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------ | ----------------- |
| `channels.connected`         | Les canaux connectés dans l’espace de travail                                                                            | `channel:read`    |
| `channels.toReconnect`       | Ceux à [reconnecter](/developers/embedding#reconnect), comme l’a dit `channel.reconnect_needed`                          | `channel:read`    |
| `channels.off`               | Ceux désactivés, sur lesquels rien ne part                                                                               | `channel:read`    |
| `posts.scheduledNext7Days`   | Les publications qui partent dans les 7 prochains jours                                                                  | `post:read`       |
| `posts.awaitingApproval`     | Les publications en attente d’une [approbation](/guides/posts/review). `mayApprove` dit si la clé détient `post:approve` | `post:read`       |
| `posts.failedLast7Days`      | Les publications terminées dans les 7 derniers jours avec un canal en échec, comme l’a dit `post.failed`                 | `post:read`       |
| `posts.unconfirmedLast7Days` | Les publications des 7 derniers jours avec un canal peut-être en ligne, à vérifier, comme l’a dit `post.unconfirmed`     | `post:read`       |
| `inbox.unanswered`           | Les fils de la [boîte de réception](/guides/engage/inbox) avec un commentaire qui attend une réponse                     | `engagement:read` |

Une section vaut `null` là où la clé n’a pas reçu la permission qui la lit. Ce n’est pas la même chose que rien à signaler : un espace de travail sans rien en cours répond des zéros. La clé a besoin de la portée `workspaces:read`.

`account.overPlan` n’arrive que sur la première page. Il dit si vos espaces de travail, qui partagent un abonnement et un compte de canaux, détiennent plus de canaux que l’abonnement ne le permet. Si c’est le cas, ils ne programment et ne publient rien tant que des canaux n’ont pas été retirés ([Abonnements et limites](#limits)). Avant votre premier client, c’est la situation de votre espace de travail principal. Il vaut `null` sur un serveur qui ne facture pas.

### Parcourir tous vos clients [#health-pages]

Les pages suivent la liste de vos espaces de travail : du plus récent au plus ancien, 50 par page sauf si `limit` dit autrement (100 au plus), avec `next` passé comme `before`. Votre espace de travail principal n’est pas listé, puisque ce n’est pas un client.

Rien ne filtre la liste pour ne garder que les espaces qui demandent votre attention : parcourez-la en entier. Pour 1 000 clients, cela fait 10 à 20 appels, bien en deçà de la [limite de requêtes](/developers/conventions/rate-limits#rate-limits).

### En tant que personne dans votre espace principal [#health-home]

Les propriétaires et administrateurs de votre espace de travail principal peuvent lire le même état à `GET /api/v1/partner/account/overview` (`partner:read`), sous **Paramètres**, puis **Partenaire**, et avec `peal partner overview` ([ligne de commande](/developers/cli/workspace#partner)).

Ils voient chaque section pour laquelle ils détiennent la permission dans l’espace principal. L’équipe d’administration qui agit en leur nom ne lit aucune boîte de réception. `mayApprove` est toujours faux pour eux, car ils ne sont membres d’aucun espace de travail client.

## Déplacer un canal vers un autre client [#move-channel]

Il arrive qu’un compte ait été connecté dans l’espace de travail du mauvais client, ou qu’il revienne désormais à un autre de vos clients. Vous pouvez y déplacer son canal. Personne ne se reconnecte : le compte, ses jetons et son état le suivent, et Peal ne demande rien à la plateforme.

```ts Node.js
  channelId,

// moved.channel.id est le nouvel identifiant du canal : gardez celui-là.
```

La réponse contient deux choses. `channel` est le canal dans l’espace de travail où il est arrivé, sous un nouvel identifiant : gardez celui-là. `postsLeft` compte les publications de l’espace qu’il a quitté qui devaient encore partir sur ce canal. Elles y échouent pour lui.

Le déplacement demande la portée `workspaces:write`, et les permissions `channel:connect` et `channel:disconnect` de la clé.

### Renvoyer un déplacement sans risque [#move-again]

Avec un en-tête `Idempotency-Key`, une requête renvoyée dans les 24 heures (après une expiration, par exemple) répond le canal que la première a déplacé, tel qu’il est maintenant, et ne déplace rien. La même clé avec une autre requête reçoit 409 `IdempotencyKeyReused`.

Sans lui, une requête renvoyée après un déplacement reçoit 404 `ChannelNotFound`, car l’ancien identifiant n’existe plus. Cherchez le compte dans l’espace de travail où il a été déplacé.

L’espace qu’il a quitté envoie [`channel.disconnected`](/developers/webhooks/events/channels#channel-disconnected), et l’autre [`channel.connected`](/developers/webhooks/events/channels#channel-connected). Les [journaux d’activité](/guides/workspace#activity) des deux espaces gardent le déplacement.

### Ce qui suit le canal [#move-what]

Le compte part, et l’essentiel de ce que l’ancien espace a construit autour de lui reste :

| Quoi                                             | Après le déplacement                                                                                                                                                                    |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Le compte, ses jetons, son état                  | Dans l’espace de travail où il est arrivé. Un canal désactivé le reste, et un canal à reconnecter le reste aussi.                                                                       |
| Son nom dans l’espace de travail                 | Laissé derrière. L’autre espace lui donne le sien.                                                                                                                                      |
| Publications, brouillons et programmées          | Restent dans l’espace où elles ont été créées. Celles qui devaient encore partir sur le canal y échouent, comme pour un canal déconnecté (`postsLeft` les compte) : modifiez-les avant. |
| Files d’attente, groupes de canaux, répétitions  | Restent, et passent le canal comme un canal déconnecté.                                                                                                                                 |
| Statistiques                                     | Les chiffres restent dans l’espace qu’il a quitté, gardés une semaine comme ceux d’un canal déconnecté, et reviennent s’il y revient dans la semaine. L’autre espace repart de zéro.    |
| Fils de la boîte de réception et messages privés | S’arrêtent dans l’espace qu’il a quitté, comme pour un canal déconnecté. L’autre espace relit à neuf les commentaires et messages du compte.                                            |
| Abonnement et utilisation                        | Vos espaces de travail partagent un abonnement : le déplacement ne compte aucun canal de plus, et aucune limite de l’abonnement ne le refuse.                                           |

### Quand un déplacement est refusé [#move-errors]

Un déplacement peut recevoir ces erreurs :

| Réponse                    | Pourquoi                                                                                                                                                                                                                                                                                                                                     |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 404 `WorkspaceNotFound`    | L’un des deux espaces n’appartient pas à votre compte partenaire. Cela comprend votre espace de travail principal et ceux des autres.                                                                                                                                                                                                        |
| 404 `ChannelNotFound`      | L’espace de travail n’a aucun canal avec cet identifiant                                                                                                                                                                                                                                                                                     |
| 409 `ChannelAccountTaken`  | L’espace de destination a déjà un canal du même compte (`channelId`), ou c’est celui où il se trouve                                                                                                                                                                                                                                         |
| 409 `IdempotencyKeyReused` | La `Idempotency-Key` a servi pour une autre requête dans les 24 dernières heures                                                                                                                                                                                                                                                             |
| 409 `WorkspaceBusy`        | Un appel passe par le canal pour l’espace qu’il quitte (une publication, un changement d’une publication en ligne, une relance, une réponse, une réponse à un avis, un message privé), ou une autre requête retient l’un des deux espaces plus de 5 secondes. Renvoyez-la un peu plus tard. Les lectures par le canal ne sont pas attendues. |

  Cela efface pour de bon tout ce que contient l’espace : ses canaux et leurs

## Abonnements et limites [#limits]

Sur une instance qui facture, les espaces de travail que possède votre compte partenaire n’ont pas d’abonnement à eux. Avec votre espace de travail principal, ils forment le compte de facturation de votre compte partenaire. Un seul abonnement, sur l’espace principal, paie le tout, sur une facture par mois.

Chaque limite se compte ainsi :

| Limite                                                       | Comment elle se compte                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Canaux                                                       | Ensemble. Les comptes gratuits et le barème de la [tarification par compte](/guides/workspace/billing#pricing) comptent comme un seul les canaux de votre espace principal et de chaque espace que vous possédez. Sur l’offre gratuite, connecter un canal de plus que ce qu’elle comprend reçoit 402 `PlanLimitReached`, et une page hébergée dit qu’aucun autre compte ne peut être connecté pour l’instant. Avec un moyen de paiement, chacun est facturé selon le barème. |
| Compteurs d’utilisation                                      | Ensemble. L’allocation mensuelle de chaque [compteur](/guides/workspace/billing#meters) couvre tous vos espaces de travail.                                                                                                                                                                                                                                                                                                                                                   |
| Médias stockés, requêtes par jour à l’assistant de rédaction | Ensemble aussi. Ils couvrent votre espace de travail principal et chaque espace de travail que vous possédez, comme pour un seul payeur. Un client qui dépense les requêtes du jour n’en laisse aucune aux autres avant minuit UTC. Les images du propre fournisseur d’images d’un client, et les requêtes à son propre fournisseur de texte, ne comptent dans aucune.                                                                                                        |
| Publications programmées dans un mois                        | Illimitées. Sur un abonnement tarifé par canaux qui les limite, chaque espace de travail reçoit ce que l’abonnement donne.                                                                                                                                                                                                                                                                                                                                                    |

<Callout
  type="warning"
  title="Au-delà de l’abonnement, vos espaces de travail ne publient rien"
>
  Si votre abonnement descend sous ce que vous détenez, rien n’est supprimé.
  Mais tant que les canaux détenus n’y sont pas revenus, en en déconnectant ou
  en ajoutant un moyen de paiement, vos espaces de travail ne programment et ne
  publient rien ([Un espace de travail au-delà de son
  abonnement](/guides/workspace/billing#over)).
</Callout>

Un Peal auto-hébergé sans facturation ne limite rien. `GET /api/v1/partner` répond ce que le compte détient chaque jour, et [son utilisation par client](#usage) ce que chaque espace a utilisé. C’est ce que compterait un prix par espace de travail ou par canal connecté.

La réponse a ces champs :

| Champ        | Ce qu’il contient                                                                                                                                                                   |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `current`    | Les espaces de travail que vous possédez maintenant, et les canaux connectés dans ceux-ci et dans votre espace principal, que compte la limite de canaux de votre abonnement        |
| `days`       | Pour chaque jour, les espaces de travail et les canaux tels que le décompte quotidien les a trouvés à 23:41 UTC (null pour un jour sans décompte), et les publications parties      |
| `totals`     | Les publications de la période par plateforme, ses jours-canaux et, pour chaque mois calendaire qu’elle touche, les publications sur les plateformes qui facturent à la publication |
| `workspaces` | Une page d’espaces de travail, [ci-dessous](#usage-workspaces)                                                                                                                      |

`current`, `days` et `totals` couvrent tout le compte : ils n’arrivent donc qu’avec la première page. Ils valent `null` sur les pages suivantes, qui ne lisent que leurs propres espaces.

### Par espace de travail [#usage-workspaces]

`workspaces` en est une page, dans l’ordre et avec le curseur de [`GET /api/v1/partner/workspaces`](/developers/embedding#workspaces) : du plus récent au plus ancien, 50 par page sauf si `limit` dit autrement (100 au plus). Passez `next` comme `before` pour la page suivante. Votre espace de travail principal vient en premier, sur la première page seulement, avec `home: true`, un de plus que demandé.

Chacun donne son `externalId` et les canaux qu’il a connectés lui-même maintenant. Sur la période, il donne ses jours-canaux, ses publications par plateforme, ses requêtes à l’assistant de rédaction, son dernier stockage de médias et ses publications facturées au compteur.

Un client retiré pendant la période n’est plus listé, et ses publications quittent les sommes, car ses décomptes ont été effacés avec lui. Les `workspaces` et `channels` quotidiens le comptent toujours pour les jours où il existait.

Les décomptes quotidiens sont gardés {{keep-partner-usage-fr}}. Ce sont des décomptes seulement, et rien n’y est tarifé. Un Peal auto-hébergé sans facturation répond `plan` et `allowances` à null.

## Où sont les choses [#surfaces]

| Voir quels clients demandent votre attention       | `GET /api/v1/partner/overview`, avec la clé, `partner.overview` dans les SDK, `peal partner overview` et **Paramètres**, puis **Partenaire**, en tant que personne ([Santé](#health))                       |
| Créer un lien à la main pour l’un de vos espaces   | `peal links create` ([ligne de commande](/developers/cli/workspace#links)), ou l’outil MCP `create_connect_link` ([MCP](/developers/mcp/tools#tools))                                                       |

La [référence de l’API](/reference) liste chaque point d’accès avec ses erreurs. Les [SDK](/developers/sdks) sont générés à partir du même contrat, en huit langages. Une clé partenaire peut se vérifier avec `GET /api/v1/credential` (`credential.get`), qui nomme son partenaire, ses portées et ses permissions, et jamais ses espaces de travail.

### Sans compte partenaire [#agencies]

Les liens de connexion marchent dans n’importe quel espace de travail. Un membre qui peut connecter des canaux, ou une clé d’API avec `channel:connect`, peut en créer un à remettre à qui possède un compte, comme le client d’une agence. Un tel lien ne prend pas de `returnUrl`, et sa page se termine en disant que le compte est connecté.

## Pas encore là [#later]

Ces parties de l’intégration ne sont pas construites :

- Votre propre sélecteur de comptes. Le choix entre plusieurs comptes se fait sur la page hébergée de Peal.
- Vos propres applications sur les plateformes. Vos clients autorisent l’application de Peal sur chaque plateforme, et l’écran de consentement de la plateforme affiche son nom.
- Votre propre domaine pour les pages hébergées, et des pages sans le nom de Peal.
