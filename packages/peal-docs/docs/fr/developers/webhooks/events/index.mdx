Un point de terminaison s’abonne aux types d’événements ci-dessous, et ne reçoit que ceux-là. Chaque type mène à ses champs et à un exemple de contenu. Le `data` de chaque événement contient `workspaceId`, l’espace de travail où il s’est produit.

### Un événement par canal [#per-channel]

Une publication part sur chacun de ses canaux séparément : `post.published`, `post.failed` et `post.unconfirmed` nomment donc un canal chacun, et une publication sur trois canaux amène trois événements. Ces champs disent lequel :

| Champ       | Type           | Ce qu’il contient                                                                                                                                                                                                                                                                                                                    |
| ----------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `targetId`  | chaîne         | La publication sur ce canal : l’identifiant de la cible, comme les listent les `targets` de l’API                                                                                                                                                                                                                                    |
| `channelId` | chaîne         | Le canal                                                                                                                                                                                                                                                                                                                             |
| `platform`  | chaîne ou null | La plateforme du canal, comme `mastodon` ; null une fois le canal déconnecté                                                                                                                                                                                                                                                         |
| `round`     | entier         | Combien de fois la publication y a été envoyée : 1, et un de plus chaque fois qu’elle a été renvoyée                                                                                                                                                                                                                                 |
| `parts`     | objet          | Pour une publication en plusieurs parties, un [fil](/guides/posts#threads) : `count`, le nombre de parties qu’elle y a (1 pour une publication seule), et `live`, combien sont en ligne. Les parties partent dans l’ordre : une publication qui a échoué ou reste à vérifier s’est arrêtée à la partie qui suit la dernière en ligne |

### webhook.test [#webhook-test]

Quelqu’un a demandé un événement de test sur le point de terminaison. Il est envoyé à ce point de terminaison seul, quels que soient ses abonnements, et aucun point de terminaison ne s’y abonne.

| Champ         | Type   | Ce qu’il contient       |
| ------------- | ------ | ----------------------- |
| `workspaceId` | chaîne | L’espace de travail     |
| `endpointId`  | chaîne | Le point de terminaison |

```json title="webhook.test"
{
  "id": "019a6f40-2f6b-7a1c-9d2e-5b4c3a2f1e0c",
  "type": "webhook.test",
  "version": 1,
  "timestamp": "2026-11-10T08:12:00.000Z",
  "workspaceExternalId": null,
  "data": {
    "workspaceId": "7b1f6c1e-2d4a-4f0b-9c3e-5a8d2e6f1b90",
    "endpointId": "019a6e00-77aa-7f12-b0c4-1a2b3c4d5e6f"
  }
}
```

### Exemples d’un type [#samples]

Un test peut porter à la place un exemple de n’importe quel type d’événement : dans l’application web, choisissez le type à côté de **Envoyer un événement de test** ; par l’API, ajoutez `?eventType=post.published` à l’adresse du test. Il est envoyé quels que soient les abonnements ou les filtres du point de terminaison.

L’exemple a la forme réelle du type, des identifiants qui ne désignent rien (`00000000-0000-7000-8000-…`), l’identifiant de l’espace de travail lui-même, et `"sample": true` à côté des autres champs du corps. Le corps d’un fait n’a jamais `sample`.

<Callout type="warning" title="N’agissez jamais sur un exemple">
  Lisez `sample` pour que votre serveur distingue un exemple d’un fait.
</Callout>

```json title="sample post.published"
{
  "id": "019a6f40-2f6b-7a1c-9d2e-5b4c3a2f1e0d",
  "type": "post.published",
  "version": 1,
  "timestamp": "2026-11-10T08:12:00.000Z",
  "workspaceExternalId": null,
  "sample": true,
  "data": {
    "workspaceId": "7b1f6c1e-2d4a-4f0b-9c3e-5a8d2e6f1b90",
    "postId": "00000000-0000-7000-8000-000000000001",
    "targetId": "00000000-0000-7000-8000-000000000002",
    "channelId": "00000000-0000-7000-8000-000000000003",
    "platform": "mastodon",
    "round": 1,
    "parts": { "count": 1, "live": 1 },
    "permalink": "https://social.example/@peal_example/1",
    "publishedAt": "2026-01-01T09:00:00.000Z"
  }
}
```
