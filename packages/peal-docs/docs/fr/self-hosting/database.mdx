Vous donnez à Peal une seule base Postgres, que nomme `DATABASE_URL`, et il y garde ses données et ses tâches durables. Vous n’avez pas à lancer les migrations vous-même : le serveur s’en charge.

## Ce que fait le serveur au démarrage [#database]

Au démarrage, le serveur applique les migrations de la base de données qu’il n’a pas encore appliquées, un serveur à la fois. Il ne commence à écouter qu’une fois qu’elles sont terminées.

Chaque partie de Peal range ses tables dans un schéma Postgres à elle : `assistant`, `auth`, `channels`, `legal`, `media`, `notifications` et `publishing`. Les tables de l’exécuteur de tâches (`cluster_*`) sont dans `public`.

### Le laisser créer `pg_trgm` [#pg-trgm]

Les migrations créent l’extension `pg_trgm`, que lit la recherche de la médiathèque. Elle est livrée avec PostgreSQL, et comme c’est une extension de confiance, le propriétaire de la base de données peut la créer.

Sur un Postgres géré, vous avez deux façons d’y arriver :

- Connectez le serveur en tant que propriétaire de la base.
- Créez l’extension une fois au préalable, avec `CREATE EXTENSION pg_trgm;`.

Ses classes d’opérateurs doivent aussi être accessibles par le chemin de recherche du rôle qui migre. Certains fournisseurs rangent les extensions dans un schéma à part, comme `extensions`. Ajoutez alors ce schéma au `search_path` du rôle avant de démarrer le serveur :

```sql
ALTER ROLE … SET search_path = "$user", public, extensions;
```

Sinon, la migration s’arrête sur « operator class gin_trgm_ops does not exist ».

### Le laisser lire sur quel cluster il tourne [#cluster-identity]

Les nettoyages des médias lisent sur quel cluster Postgres tourne la base, pour distinguer une base restaurée de celle qu’elle était ([À quelle base appartient le dossier](/self-hosting/storage#media-owner)). Ils appellent `pg_control_system()`, et lisent la timeline depuis `pg_walfile_name(pg_current_wal_lsn())`.

PostgreSQL tel quel laisse tout rôle les appeler. Un Postgres géré qui les refuse fait échouer à chaque passage les deux nettoyages qui suppriment. Ils ne suppriment rien, et l’alerte `peal-media-sweep-failing` se déclenche.

Un clone ou une branche d’un fournisseur qui garde l’identifiant système et la timeline n’est repéré que par l’époque des nettoyages. Donnez à un clone un préfixe de médias à lui.

## Le connecter directement [#connections]

Le serveur exécute ses tâches durables depuis la même base. Il les garde par des verrous consultatifs de session tant qu’il tourne.

<Callout type="warning" title="Un pooler en mode transaction ne convient pas">
  Connectez le serveur à Postgres directement, ou par un pooler en mode session.
  Un pooler en mode transaction donne une autre connexion à chaque requête, et
  le serveur perd ces verrous.
</Callout>

Ces réglages dimensionnent les connexions et les traces des tâches :

| Réglage                  | Par défaut | Ce qu’il fait                                                                                                                              |
| ------------------------ | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `DATABASE_URL`           | aucune     | La base Postgres. Chaque processus serveur y ouvre jusqu’à `DATABASE_POOL_MAX` connexions.                                                 |
| `DATABASE_POOL_MAX`      | `20`       | Les connexions que chaque processus serveur y ouvre au plus, pour l’API et les tâches.                                                     |
| `AUTH_DB_POOL_MAX`       | `5`        | Les connexions que chaque processus serveur ouvre en plus, pour la connexion des utilisateurs.                                             |
| `PEAL_CLUSTER_RETENTION` | `30 days`  | Un nettoyage quotidien supprime les traces des tâches terminées depuis plus longtemps. Les tâches encore en attente sont toujours gardées. |

[Variables d’environnement](/self-hosting/environment-variables#core) détaille chacun, avec `AUTH_DB_POOL_MAX` sous [Connexion](/self-hosting/environment-variables#sign-in).
