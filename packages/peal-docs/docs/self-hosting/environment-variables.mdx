The server, the web app and the command line read plain environment variables, so they run on any host. This page lists every one they read. Values shown are examples.

The server runs in production mode when `NODE_ENV` is `production`, as its image sets. Settings marked "required in production" have no default there, and the server refuses to start without them. Elsewhere they default to the development stack, so a server run from source needs only `DATABASE_URL`.

## Server [#server]

### Core [#core]

MCP clients sign in only when it is HTTPS, or on a loopback host such as `localhost`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |

| `HOSTNAME`                      | `peal-server`                                   | The server's name among the job runners recorded in the database. Each server process needs its own; Docker sets it to the container id.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `PEAL_CLUSTER_RETENTION`        | `30 days`                                       | How long the records of finished jobs, such as a published post's, are kept before a daily cleanup deletes them, as a duration such as `7 days`. Jobs still waiting are always kept.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `PEAL_ANALYTICS_CONCURRENCY`    | `16`                                            | How many channels the hourly collections of post counts and of accounts' followers each read at the same time, each one call at a time, from `1` to `256`. A run stops 50 minutes after its time and leaves the rest to the next: raise this when the server logs that the collection could not finish, and the metric `peal.analytics.collection.left` stays above zero. Another value stops the server.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `PEAL_ENGAGEMENT_CONCURRENCY`   | `8`                                             | How many channels the collection of comments, which runs every ten minutes, reads at the same time, each one call at a time, from `1` to `256`. A run stops 8 minutes after its time and leaves the rest to the next: raise this when the server logs that the comments collection could not finish before the next run.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `PEAL_ENGAGEMENT_WINDOW_DAYS`   | `30`                                            | How many days after a post went live Peal reads the comments under it, from `1` to `90`. Comments are other people's personal data, and each thread is deleted {{keep-inbox-en}} after its window ends: a longer window keeps them longer, so say so in your privacy policy. See [Inbox](/guides/engage/inbox#retention).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `PEAL_INBOX_PLATFORMS`          | unset                                           | The platforms whose comments the [inbox](/guides/engage/inbox#meta) reads beside Mastodon and Bluesky, comma-separated among `facebook`, `instagram`, `youtube`, `linkedin` and `googleBusiness`. Unset or empty, none. Posts may then also carry a [first comment](/guides/posts#first-comment) there, which takes the same permission; taking a platform out refuses, when its time comes and before anything goes out, a post already scheduled there with a first comment. Their sign-ins then ask, as optional, for the comment permissions, which Meta grants for accounts other than your own app's people's only after its App Review, and Google only once it verified your app for `youtube.force-ssl`. `facebook` needs `META_APP_ID` and `META_APP_SECRET`; `instagram` needs them or `INSTAGRAM_APP_ID` and `INSTAGRAM_APP_SECRET`; `youtube` needs `YOUTUBE_CLIENT_ID` and `YOUTUBE_CLIENT_SECRET`; `linkedin` (company pages only) needs `LINKEDIN_PAGES_CLIENT_ID` and `LINKEDIN_PAGES_CLIENT_SECRET`, and an app LinkedIn granted the comment scopes, or it refuses every pages sign-in. `googleBusiness` reads the [reviews](/guides/engage/inbox#reviews) of Google Business Profile locations, and needs `GOOGLE_BUSINESS_CLIENT_ID` and `GOOGLE_BUSINESS_CLIENT_SECRET`, and a project Google gave access to the Business Profile APIs (its quota is zero before); its sign-in asks nothing more. Taking `linkedin` out forgets, within a day, the member who connected each page, so each page's calls are counted alone once it is back, until the page is reconnected. Any other name, or a platform without its app, stops the server at startup. |
| `PEAL_INBOX_MESSAGES`           | unset                                           | The platforms whose [direct messages](/guides/engage/inbox#direct-messages) the inbox reads and answers, comma-separated among `mastodon` and `bluesky`. Unset or empty, none: messages are private correspondence, read only once you say so. `bluesky` lets Peal ask for the chat methods' scopes (in its client metadata), but a sign-in asks for them only when a member turns a Bluesky channel's messages on, which reconnects the account. Even so, a channel's messages are read only once a member of its workspace turns them on for it. Peal keeps each message 30 days after it was sent, and deletes a channel's conversations at once when its messages are turned off or it is disconnected. Any other name stops the server at startup.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `PEAL_API_REQUESTS_PER_MINUTE`  | `600`                                           | How many requests a minute each API key, and each OAuth application for each user it acts for, may send to the API and the MCP endpoint together: a positive integer. Sessions of the web app are not counted. On a server that bills, it is the limit of billing accounts with a payment method or a plan priced by channels; one without a payment method sends the rate card's {{api-without-en}}, and staff may give a workspace its own limit. Every answer says what is left in the `RateLimit` headers, and past the limit the server answers 429 ([Rate limits](/developers/conventions/rate-limits#rate-limits)). A value that is not a positive integer stops the server at startup.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `PEAL_DOCS_URL`                 | unset                                           | The address of your copy of this documentation, such as `https://docs.example.com`. With it, the documents that tell programs where the API and the MCP endpoint are (`/.well-known/api-catalog` and `/llms.txt`) link to its pages; without it, they link to no documentation ([Discovery](/developers/conventions/discovery#discovery)). A value that is not a URL stops the server at startup.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `PEAL_LEGAL_RETENTION`          | `false`                                         | Whether the server keeps what French law has a host keep to identify whoever contributed content: the connections that create, change or delete content ({{keep-legal-connections-en}}), and, once an account closes, its holder's name and address ({{keep-legal-identity-en}}) and how they signed in ({{keep-legal-account-en}}), readable only through a legal request. Set it to `true` if you are established in France, or offer your Peal there, and store content for other people; leave it off otherwise. [Legal retention](/self-hosting/privacy#legal-retention) says who must, and what turning it off again does.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `PEAL_PRIVACY_DECLARATION_FILE` | none                                            | The path of a JSON file that declares what only you know about your processing: who the controller is and how to reach it, your privacy policy's address, the providers you use and your supervisory authority. Each user's data export repeats it ([Privacy declaration](/self-hosting/privacy#privacy-declaration)). Unset, the export says none was declared; a file that is missing or malformed stops the server. The Compose stack sets it, and mounts the file `PEAL_PRIVACY_DECLARATION` names.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

### Sign-in [#sign-in]

| Variable                          | Default                                      | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| --------------------------------- | -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BETTER_AUTH_SECRET`              | required in production; a development secret | The secret that signs sessions and encrypts what sign-in stores: at least 32 random characters, such as `openssl rand -base64 32`. Whoever knows it can sign in as anyone. Keep it secret. It also encrypts the keys and recovery codes of [two-step verification](/guides/workspace/account#two-step): replacing it without keeping the old one in `BETTER_AUTH_SECRETS` makes them unreadable, and nobody who has it on can sign in until staff reset it. |
| `BETTER_AUTH_SECRETS`             | unset                                        | To rotate the secret: `version:secret` entries separated by commas, newest first, such as `2:<new>,1:<old>`. Read by Better Auth itself: when set, the first entry's secret is used, and the others, with `BETTER_AUTH_SECRET`, still decrypt what older secrets encrypted.                                                                                                                                                                                 |
| `AUTH_IP_HEADERS`                 | required in production; `x-forwarded-for`    | The headers, separated by commas, that carry the client's address, which sign-in rate limits and the web app's error reports count by. Name only a header your edge sets and replaces: `cf-connecting-ip` behind Cloudflare, `x-forwarded-for` behind Caddy. The docs server reads it too, for its assistant's rate limit. See [In front of Peal](/self-hosting#reverse-proxy).                                                                             |
| `AUTH_TRUSTED_PROXIES`            | none                                         | The addresses or CIDR ranges, separated by commas, of proxies that append to `X-Forwarded-For`. The client's address is then read from the right, past them.                                                                                                                                                                                                                                                                                                |
| `TRUSTED_ORIGINS`                 | none                                         | Origins besides `PUBLIC_URL`, separated by commas, allowed to send signed-in requests that change something. `media-cors` also lets them upload media.                                                                                                                                                                                                                                                                                                      |
| `AUTH_REQUIRE_EMAIL_VERIFICATION` | `true`                                       | `false` lets people sign in before they confirm their email address.                                                                                                                                                                                                                                                                                                                                                                                        |
| `AUTH_DB_POOL_MAX`                | `5`                                          | How many database connections sign-in opens, beside the server's 10.                                                                                                                                                                                                                                                                                                                                                                                        |
| `MCP_DYNAMIC_REGISTRATION`        | `false`                                      | `true` lets MCP clients register themselves, which most of them need before they sign in. Anyone may then register a client under any name; the consent page says Peal has not checked it.                                                                                                                                                                                                                                                                  |
| `PEAL_PARTNER_SELF_SERVICE`       | `false`                                      | `true` lets the owners and admins of any workspace open a [partner account](/developers/embedding) for it themselves, in its settings. Unset or `false`, only staff open one, from the [staff console](/self-hosting/staff#partners). Another value stops the server.                                                                                                                                                                                       |
| `PEAL_STAFF_TWO_STEP`             | `false`                                      | `true` refuses the [staff console](/self-hosting/staff#two-step) to staff whose own account does not have [two-step verification](/guides/workspace/account#two-step) on; anyone else still finds no console. Members turn it on themselves, and owners may require it of a workspace: neither needs a setting. Another value stops the server.                                                                                                             |
| `PEAL_SIGN_UP`                    | `open`                                       | Who may make an account. `open` lets anyone; `invitation` only whoever opens a pending invitation's link and signs up with the address it went to, and the first account of a server that has none ([Who may sign up](/self-hosting/options#sign-up)). Another value stops the server.                                                                                                                                                                      |

Better Auth also reads `BETTER_AUTH_TRUSTED_ORIGINS`, which adds origins as `TRUSTED_ORIGINS` does. Prefer `TRUSTED_ORIGINS`, which `media-cors` reads too.

### Email [#email]

| Variable         | Default                                                                   | What it does                                                                                                                                                                                   |
| ---------------- | ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MAIL_FROM`      | required in production; `Peal <noreply@peal.localhost>`                   | The sender, as `Peal <noreply@example.com>` or an address your mail service may send from.                                                                                                     |
| `RESEND_API_KEY` | unset                                                                     | Sends email through Resend's API. Keep it secret.                                                                                                                                              |
| `SMTP_URL`       | required in production without `RESEND_API_KEY`; `smtp://127.0.0.1:11025` | The SMTP server, such as `smtp://user:password@mail.example.com:587`, or `smtps://` for TLS from the first byte. Used when `RESEND_API_KEY` is unset. Keep it secret when it holds a password. |

### Channels [#channels]

| `PEAL_TOKEN_KEYS`                         | unset    | The keys that encrypt the tokens of connected channels and the signing secrets of [webhooks](/developers/webhooks#self-hosting), and the keys of the image and text providers workspaces bring to the [assistant](/guides/workspace#text-provider): `keyId:key` entries separated by commas, such as `k2:<key>,k1:<key>`, each key 32 random bytes in base64 (`openssl rand -base64 32`). The first key encrypts and every listed key decrypts. Unset or empty, the server starts, and connecting a channel or adding a webhook endpoint fails. A malformed value stops the server at startup. | `PEAL_OUTBOUND_ALLOWED_HOSTS`             | unset    | Hosts on your own network that members may name, such as a website on a private address: host names or addresses, separated by commas, without a scheme, port or wildcard. A host listed here is open to everything members name, not only websites: media imported from a link, Mastodon and Bluesky servers, webhooks' endpoints, feeds and assistant providers. ### Telemetry [#telemetry]

| Variable                      | Default                                                                     | What it does                                                                                                                                                                                                                                                                              |
| ----------------------------- | --------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | unset                                                                       | The OTLP/HTTP address of the OpenTelemetry collector that receives logs, metrics and traces, such as `http://otel-collector:4318`. Unset, nothing is exported.                                                                                                                            |
| `OTEL_SERVICE_NAME`           | `peal-server`                                                               | The service name telemetry is reported under.                                                                                                                                                                                                                                             |
| `OTEL_TRACES_EXPORTER`        | `otlp`                                                                      | `none` stops exporting traces once an endpoint is set. `OTEL_METRICS_EXPORTER` and `OTEL_LOGS_EXPORTER` do the same for metrics and logs.                                                                                                                                                 |
| `OTEL_TRACES_SAMPLER`         | `parentbased_traceidratio` in production, `parentbased_always_on` elsewhere | Which traces are exported, by OpenTelemetry's sampler names: `always_on`, `always_off`, `traceidratio`, `parentbased_always_on`, `parentbased_always_off` or `parentbased_traceidratio`. The `parentbased_` ones follow the decision a request came with. Another value stops the server. |
| `OTEL_TRACES_SAMPLER_ARG`     | `0.1` in production, `1` elsewhere                                          | The share of traces the `traceidratio` samplers keep, from `0` to `1`. Production keeps one trace in ten unless you say otherwise.                                                                                                                                                        |

The sampler decides when a trace begins, before anyone knows how it ends. So that the traces you look for are there, whatever the ratio:

- every attempt to publish a post on a channel is traced, with the calls to the platform under it;
- from a trace that was not sampled, the server still exports the spans that ended in a bug, the requests it answered with a `5xx`, and the spans that lasted 10 seconds or more, each with the spans above it;
- logs and metrics are never sampled: every error is logged with its trace id, and every request is counted in the metric `peal.http.requests`, by status class, which the stack's alerts read.

`always_off` and `parentbased_always_off` turn all of this off: no trace begins on the server.

The server exports telemetry as JSON over HTTP, so point the endpoint at the collector's OTLP/HTTP port, 4318 by default, rather than its gRPC one. It also reads these OpenTelemetry variables, and no others (`OTEL_EXPORTER_OTLP_PROTOCOL` included):

- `OTEL_EXPORTER_OTLP_HEADERS`, `OTEL_EXPORTER_OTLP_COMPRESSION` and `OTEL_EXPORTER_OTLP_TIMEOUT`, and the per-signal forms of these and of the endpoint, such as `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT`;
- `OTEL_RESOURCE_ATTRIBUTES` and `OTEL_SERVICE_VERSION`;
- `OTEL_SDK_DISABLED`;
- the batching settings `OTEL_BSP_*` for traces and `OTEL_BLRP_*` for logs;
- `OTEL_METRIC_EXPORT_INTERVAL`, `OTEL_METRIC_EXPORT_TIMEOUT` and `OTEL_EXPORTER_OTLP_METRICS_TEMPORALITY_PREFERENCE`.
