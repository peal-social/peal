The server, the web app and the command line read plain environment variables, so you can run them on any host. The values on this page are examples.

The server runs in production mode when `NODE_ENV` is `production`, which its image sets. In production, a setting marked "required in production" has no default, and the server won't start without it. Elsewhere it defaults to the development stack, so a server you run from source needs only `DATABASE_URL`.

## Server [#server]

### Core [#core]

The server needs `DATABASE_URL` to start, and `PUBLIC_URL` too in production. The rest are optional:

| Variable                        | Default                                         | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------------------- | ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`                  | none: required                                  | The Postgres database, such as `postgres://peal:secret@postgres:5432/peal`. Connect directly, or through a pooler in session mode. Never use a pooler in transaction mode.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `PUBLIC_URL`                    | required in production; `http://localhost:3001` | The address people open Peal at, which is the web app's, such as `https://peal.example.com`. Peal builds the links in emails, sign-in, the platforms' redirects and the MCP endpoint's address from its origin. MCP clients can sign in only when it's HTTPS, or on a loopback host such as `localhost`. If you change it, give the platforms their new addresses ([Addresses to register](/self-hosting/platforms#platform-addresses)).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `NODE_ENV`                      | `development`                                   | `production` turns on production mode, with required settings, sign-in rate limits and no development defaults.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `PORT`                          | `3000`                                          | The port the HTTP server listens on.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `HOSTNAME`                      | `peal-server`                                   | The server's name among the job runners recorded in the database. Each server process needs its own. Docker sets it to the container id.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `PEAL_CLUSTER_RETENTION`        | `30 days`                                       | How long Peal keeps the records of finished jobs, such as a published post's, before a daily cleanup deletes them. Write it as a duration, such as `7 days`. Jobs still waiting are always kept.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `PEAL_ANALYTICS_CONCURRENCY`    | `16`                                            | How many channels the hourly collections of post counts and of accounts' followers each read at the same time, with one call at a time per channel. Use a value from `1` to `256`. Any other value stops the server. A run stops 50 minutes after its scheduled time and leaves the rest to the next one. Raise this when the server logs that the collection couldn't finish and the metric `peal.analytics.collection.left` stays above zero.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `PEAL_ENGAGEMENT_CONCURRENCY`   | `8`                                             | How many channels the collection of comments, which runs every ten minutes, reads at the same time, with one call at a time per channel. Use a value from `1` to `256`. Any other value stops the server. A run stops 8 minutes after its scheduled time and leaves the rest to the next one. Raise this when the server logs that the comments collection couldn't finish before the next run.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `PEAL_ENGAGEMENT_WINDOW_DAYS`   | `30`                                            | How many days after a post goes live Peal reads the comments under it, from `1` to `90`. Any other value stops the server. Each thread is deleted {{keep-inbox-en}} after its window ends. Comments are other people's personal data, so a longer window keeps them longer, and your privacy policy should say so. See [Inbox](/guides/engage/inbox#retention).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `PEAL_INBOX_PLATFORMS`          | unset                                           | The platforms whose comments the [inbox](/guides/engage/inbox#meta) reads besides Mastodon and Bluesky, comma-separated, among `facebook`, `instagram`, `youtube`, `linkedin` and `googleBusiness`. Unset or empty, it reads none. Posts on a platform listed here can also carry a [first comment](/guides/posts#first-comment), which takes the same permission. The platform's sign-ins then ask for the comment permissions, as optional. Meta grants them for accounts other than your own app's people only after its App Review, and Google only once it has verified your app for `youtube.force-ssl`. Each platform needs its app: `facebook` needs `META_APP_ID` and `META_APP_SECRET`, `instagram` needs them or `INSTAGRAM_APP_ID` and `INSTAGRAM_APP_SECRET`, and `youtube` needs `YOUTUBE_CLIENT_ID` and `YOUTUBE_CLIENT_SECRET`. `linkedin` (company pages only) needs `LINKEDIN_PAGES_CLIENT_ID` and `LINKEDIN_PAGES_CLIENT_SECRET`, on an app LinkedIn granted the comment scopes, or LinkedIn refuses every pages sign-in. `googleBusiness` reads the [reviews](/guides/engage/inbox#reviews) of Google Business Profile locations. It needs `GOOGLE_BUSINESS_CLIENT_ID` and `GOOGLE_BUSINESS_CLIENT_SECRET`, on a project Google gave access to the Business Profile APIs (the quota is zero until then), and its sign-in asks for nothing more. If you take a platform out, a post already scheduled there with a first comment is refused when its time comes, before anything goes out. Taking `linkedin` out also forgets, within a day, the member who connected each page, so once it's back each page's calls are counted on their own until the page is reconnected. Any other name, or a platform without its app, stops the server at startup. |
| `PEAL_INBOX_MESSAGES`           | unset                                           | The platforms whose [direct messages](/guides/engage/inbox#direct-messages) the inbox reads and answers, comma-separated, among `mastodon`, `bluesky`, `facebook` (Pages' Messenger) and `instagram`. Unset or empty, none, because messages are private correspondence that Peal reads only once you say so. With `bluesky`, Peal can ask for the chat methods' scopes, in its client metadata, and with `facebook` and `instagram` for Meta's messaging permissions. A sign-in asks for them only when a member turns a channel's messages on, which reconnects the account. `facebook` needs Meta's main app (`META_APP_ID`, `META_APP_SECRET`), `instagram` either of its ways in, and both need `META_WEBHOOK_VERIFY_TOKEN`, or the server stops at startup. Meta grants their permissions for the accounts of people without a role on the app only after its App Review ([Meta](/self-hosting/platforms#meta)). Even then, Peal reads a channel's messages only once a member of its workspace turns them on for it. On `facebook` and `instagram`, that also lets members send a comment's author its one [private reply](/guides/engage/inbox#private-replies). Peal keeps each message 30 days after it was sent. It deletes a channel's conversations at once when its messages are turned off or the channel is disconnected. Any other name stops the server at startup.                                                                                                                                                                                                                                                                                                                                                                                       |
| `PEAL_META_HUMAN_AGENT`         | `false`                                         | `true` once Meta's App Review has granted the server's Meta app its Human Agent feature, which also takes business verification. A member signed in to Peal's web app can then answer a Messenger or Instagram [direct message](/guides/engage/inbox#meta-messages) by hand until 7 days after the person's last message, past Meta's 24 hours. The answer goes out with Meta's `HUMAN_AGENT` tag. An API key, an application (the command line, an AI assistant), staff acting as a member and a rule can never send one. It does nothing while `PEAL_INBOX_MESSAGES` names neither `facebook` nor `instagram`. Leave it unset until Meta has reviewed the feature, because Meta refuses the tagged messages before that. Unset or empty, off. Any value other than `true` or `false` (`1`, `on`, `yes`…) stops the server at startup.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `PEAL_API_REQUESTS_PER_MINUTE`  | `600`                                           | How many requests a minute each API key may send to the API and the MCP endpoint together, and each OAuth application for each user it acts for. Use a positive integer. Sessions of the web app aren't counted. On a server that bills, this is the limit for billing accounts with a payment method or a plan priced by channels. A billing account without a payment method gets the rate card's {{api-without-en}}, and staff can give a workspace its own limit. Every answer says what's left in the `RateLimit` headers, and past the limit the server answers 429 ([Rate limits](/developers/conventions/rate-limits#rate-limits)). A value that isn't a positive integer stops the server at startup.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `PEAL_DOCS_URL`                 | unset                                           | The address of your copy of this documentation, such as `https://docs.example.com`. With it, the documents that tell programs where the API and the MCP endpoint are (`/.well-known/api-catalog` and `/llms.txt`) link to its pages. Without it, they link to no documentation ([Discovery](/developers/conventions/discovery#discovery)). A value that isn't a URL stops the server at startup.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `PEAL_LEGAL_RETENTION`          | `false`                                         | Whether the server keeps what French law has a host keep to identify whoever contributed content. That's the connections that create, change or delete content ({{keep-legal-connections-en}}). Once an account closes, it's also the holder's name and address ({{keep-legal-identity-en}}) and how they signed in ({{keep-legal-account-en}}), which only a legal request can read. Set it to `true` if you're established in France, or offer your Peal there, and you store content for other people. Otherwise leave it off. [Legal retention](/self-hosting/privacy#legal-retention) says who must turn it on, and what turning it off again does.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `PEAL_PRIVACY_DECLARATION_FILE` | none                                            | The path of a JSON file that declares what only you know about your processing: who the controller is and how to reach them, your privacy policy's address, the providers you use and your supervisory authority. Each user's data export repeats it ([Privacy declaration](/self-hosting/privacy#privacy-declaration)). Unset, the export says that none was declared. A file that's missing or malformed stops the server. The Compose stack sets it, and mounts the file that `PEAL_PRIVACY_DECLARATION` names.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

### Sign-in [#sign-in]

These settings cover sessions, sign-in and who can make an account:

| Variable                          | Default                                      | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| --------------------------------- | -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BETTER_AUTH_SECRET`              | required in production; a development secret | Signs sessions and encrypts what sign-in stores. Use at least 32 random characters, such as the output of `openssl rand -base64 32`. Anyone who has it can sign in as anyone, so keep it secret. It also encrypts the keys and recovery codes of [two-step verification](/guides/workspace/account#two-step). If you replace it, keep the old one in `BETTER_AUTH_SECRETS`. Without it, those keys can't be read, and nobody who has two-step verification on can sign in until staff reset it.                                                     |
| `BETTER_AUTH_SECRETS`             | unset                                        | Rotates the secret. List `version:secret` entries separated by commas, newest first, such as `2:<new>,1:<old>`. Better Auth reads it itself. When it's set, Better Auth uses the first entry's secret, and the others, with `BETTER_AUTH_SECRET`, still decrypt what older secrets encrypted.                                                                                                                                                                                                                                                       |
| `AUTH_IP_HEADERS`                 | required in production; `x-forwarded-for`    | The headers, separated by commas, that carry the client's address. Sign-in rate limits and the web app's error reports count by that address. Name only a header your edge sets and replaces: `cf-connecting-ip` behind Cloudflare, `x-forwarded-for` behind Caddy. The docs server reads it too, for its assistant's rate limit (ten questions each ten minutes per IPv4 address or IPv6 /64), and so does the web app, for the address it relays with a site's events (`PEAL_POSTHOG_SITE`). See [In front of Peal](/self-hosting#reverse-proxy). |
| `AUTH_TRUSTED_PROXIES`            | none                                         | The addresses or CIDR ranges, separated by commas, of proxies that append to `X-Forwarded-For`. Peal then reads the client's address from the right, past them.                                                                                                                                                                                                                                                                                                                                                                                     |
| `TRUSTED_ORIGINS`                 | none                                         | Origins besides `PUBLIC_URL`, separated by commas, that may send signed-in requests that change something. `media-cors` also lets them upload media.                                                                                                                                                                                                                                                                                                                                                                                                |
| `AUTH_REQUIRE_EMAIL_VERIFICATION` | `true`                                       | `false` lets people sign in before they confirm their email address. Nobody has then proven an address: anyone can register any address, and its real owner takes the account back with a password reset.                                                                                                                                                                                                                                                                                                                                           |
| `AUTH_DB_POOL_MAX`                | `5`                                          | How many database connections sign-in opens, on top of the server's 10.                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `MCP_DYNAMIC_REGISTRATION`        | `false`                                      | `true` lets MCP clients register themselves, which most of them need before they can sign in. Anyone can then register a client under any name, and the consent page says that Peal hasn't checked it.                                                                                                                                                                                                                                                                                                                                              |
| `PEAL_PARTNER_SELF_SERVICE`       | `false`                                      | `true` lets the owners and admins of any workspace open a [partner account](/developers/embedding) for it themselves, in its settings. Unset or `false`, only staff open one, from the [staff console](/self-hosting/staff#partners). Another value stops the server.                                                                                                                                                                                                                                                                               |
| `PEAL_STAFF_TWO_STEP`             | `false`                                      | `true` refuses the [staff console](/self-hosting/staff#two-step) to staff whose own account doesn't have [two-step verification](/guides/workspace/account#two-step) on. Anyone else still finds no console. Members turn two-step verification on themselves, and owners can require it in a workspace, without any setting. Another value stops the server.                                                                                                                                                                                       |
| `PEAL_SIGN_UP`                    | `open`                                       | Who can make an account. `open` lets anyone. `invitation` lets in only someone who opens a pending invitation's link and signs up with the address it went to, and the first account of a server that has none ([Who may sign up](/self-hosting/options#sign-up)). Another value stops the server.                                                                                                                                                                                                                                                  |

Better Auth also reads `BETTER_AUTH_TRUSTED_ORIGINS`, which adds origins the way `TRUSTED_ORIGINS` does. Use `TRUSTED_ORIGINS` instead, because `media-cors` reads it too.

### Sign-in providers [#sign-in-providers]

Each provider is off until you set its settings, and a group set only in part stops the server ([Single sign-on](/self-hosting/single-sign-on)). A provider takes these settings:

| Variable                       | Default                | What it does                                                                                                                                                                                                                                                                                                                                                                |
| ------------------------------ | ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PEAL_OIDC_ISSUER`             | unset: no provider     | Your OpenID Connect provider's issuer, an `https://` URL. Use `http://` only on a loopback host, to try it on one machine. Peal reads `<issuer>/.well-known/openid-configuration`. Identities are kept under the issuer, so after a change people join their accounts again by a confirmed address ([Changing the provider](/self-hosting/single-sign-on#change-provider)). |
| `PEAL_OIDC_CLIENT_ID`          | unset                  | The client ID you registered at the provider, with the redirect URI `<PUBLIC_URL>/api/auth/callback/oidc`.                                                                                                                                                                                                                                                                  |
| `PEAL_OIDC_CLIENT_SECRET`      | unset                  | Its secret. Keep it secret.                                                                                                                                                                                                                                                                                                                                                 |
| `PEAL_OIDC_NAME`               | `Single sign-on`       | The name the button shows after "Continue with". One line, 40 characters at most.                                                                                                                                                                                                                                                                                           |
| `PEAL_OIDC_SCOPES`             | `openid email profile` | The scopes Peal asks for, separated by spaces. They must include `openid` and `email`.                                                                                                                                                                                                                                                                                      |
| `GOOGLE_SIGN_IN_CLIENT_ID`     | unset: no Google       | The client ID of a Google OAuth client of type "Web application", with the redirect URI `<PUBLIC_URL>/api/auth/callback/google`. With the secret, the sign-in and sign-up pages offer Google.                                                                                                                                                                               |
| `GOOGLE_SIGN_IN_CLIENT_SECRET` | unset                  | Its secret. Keep it secret.                                                                                                                                                                                                                                                                                                                                                 |

### Email [#email]

Peal sends email through Resend when `RESEND_API_KEY` is set, and over SMTP otherwise:

| Variable                  | Default                                                                   | What it does                                                                                                                                                                                           |
| ------------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `MAIL_FROM`               | required in production; `Peal <noreply@peal.localhost>`                   | The sender, such as `Peal <noreply@example.com>`, or any address your mail service lets you send from.                                                                                                 |
| `PEAL_MAIL_PERSONAL_FROM` | unset: `MAIL_FROM`                                                        | The sender of the emails a person signs, written as `MAIL_FROM` is, such as `Ada at Example <ada@example.com>`. Every other email comes from `MAIL_FROM`.                                              |
| `RESEND_API_KEY`          | unset                                                                     | Sends email through Resend's API. Keep it secret.                                                                                                                                                      |
| `SMTP_URL`                | required in production without `RESEND_API_KEY`; `smtp://127.0.0.1:11025` | The SMTP server, such as `smtp://user:password@mail.example.com:587`, or `smtps://` for TLS from the first byte. Peal uses it when `RESEND_API_KEY` is unset. Keep it secret when it holds a password. |
| `PEAL_MAIL_IDENTITY`      | unset: no line                                                            | Who sends, such as `Example SAS`, on one line under every email and at the end of its text version. 300 characters at most. A value with a line break, or a longer one, stops the server at startup.   |
| `PEAL_MAIL_IDENTITY_FR`   | unset: French readers get `PEAL_MAIL_IDENTITY`                            | The same line for French readers, in their language. It has the same limits.                                                                                                                           |

### Channels [#channels]

Members can connect a platform once you've set its app's settings. [Platform apps](/self-hosting/platforms) shows how to register each app:

| Variable                                  | Default  | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ----------------------------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PEAL_TOKEN_KEYS`                         | unset    | The keys that encrypt the tokens of connected channels, the signing secrets of [webhooks](/developers/webhooks#self-hosting), and the keys of the image and text providers that workspaces bring to the [assistant](/guides/workspace#providers). List `keyId:key` entries separated by commas, such as `k2:<key>,k1:<key>`, with each key 32 random bytes in base64 (`openssl rand -base64 32`). The first key encrypts, and every listed key decrypts. Unset or empty, the server starts, but connecting a channel or adding a webhook endpoint fails. A malformed value stops the server at startup. Keep a copy: without the keys, every channel has to be reconnected, and no webhook delivery can be signed.                                                                                                                                                                            |
| `PEAL_OUTBOUND_ALLOWED_HOSTS`             | unset    | Hosts on your own network that members may name, such as a website on a private address. List host names or addresses, separated by commas, with no scheme, port or wildcard, and put an IPv6 address in brackets (`[fd00::10]`). Peal reaches what members name (a Mastodon server, a website, a feed, an assistant provider) over HTTPS on the default port, and only at public addresses. It reaches a host listed here whatever its address, still over HTTPS on the default port. Everything members name can then reach that host: websites, media imported from a link, Mastodon and Bluesky servers, webhook endpoints, feeds and assistant providers. List only hosts you'd trust every member with, because this is how a request could reach a service inside your network. Anything but host names stops the server at startup, and so does an IPv6 address without its brackets. |
| `BLUESKY_CLIENT_KEYS`                     | unset    | The keys of Peal's Bluesky client, from `bun nx run peal-server:bluesky-key`. A malformed value stops the server at startup.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `LINKEDIN_CLIENT_ID`                      | unset    | The client id of the app you registered on LinkedIn, with the OpenID Connect and Share on LinkedIn products (see [LinkedIn](/self-hosting/platforms#linkedin)). | `LINKEDIN_CLIENT_SECRET`                  | unset    | The app's primary client secret. Keep it secret.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `LINKEDIN_PAGES_CLIENT_ID`                | unset    | The client id of a second LinkedIn app, which has the Community Management API and no other product (see [LinkedIn company pages](/self-hosting/platforms#linkedin-pages)). One without the other stops the server at startup.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `LINKEDIN_PAGES_CLIENT_SECRET`            | unset    | That app's primary client secret. Keep it secret.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `LINKEDIN_API_VERSION`                    | `202610` | The version of LinkedIn's API that Peal calls, as `YYYYMM`. ### Telemetry [#telemetry]

The server exports nothing until you set an OTLP endpoint:

| Variable                      | Default                                                                     | What it does                                                                                                                                                                                                                                                                              |
| ----------------------------- | --------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | unset                                                                       | The OTLP/HTTP address of the OpenTelemetry collector that receives logs, metrics and traces, such as `http://otel-collector:4318`. Unset, nothing is exported.                                                                                                                            |
| `OTEL_SERVICE_NAME`           | `peal-server`                                                               | The service name that telemetry is reported under.                                                                                                                                                                                                                                        |
| `OTEL_TRACES_EXPORTER`        | `otlp`                                                                      | `none` stops exporting traces once an endpoint is set. `OTEL_METRICS_EXPORTER` and `OTEL_LOGS_EXPORTER` do the same for metrics and logs.                                                                                                                                                 |
| `OTEL_TRACES_SAMPLER`         | `parentbased_traceidratio` in production, `parentbased_always_on` elsewhere | Which traces are exported, by OpenTelemetry's sampler names: `always_on`, `always_off`, `traceidratio`, `parentbased_always_on`, `parentbased_always_off` or `parentbased_traceidratio`. The `parentbased_` ones follow the decision a request came with. Another value stops the server. |
| `OTEL_TRACES_SAMPLER_ARG`     | `0.1` in production, `1` elsewhere                                          | The share of traces the `traceidratio` samplers keep, from `0` to `1`. Production keeps one trace in ten unless you set otherwise.                                                                                                                                                        |

The sampler decides when a trace begins, before anyone knows how it ends. Whatever the ratio, the server keeps the traces you'll look for:

- Every attempt to publish a post on a channel is traced, with the calls to the platform under it.
- From a trace that wasn't sampled, the server still exports the spans that ended in a bug, the requests it answered with a `5xx`, and the spans that lasted 10 seconds or more, each with the spans above it.
- Logs and metrics are never sampled. Every error is logged with its trace id, and every request is counted in the metric `peal.http.requests`, by status class, which the stack's alerts read.

`always_off` and `parentbased_always_off` turn all of this off, and no trace begins on the server.

The server exports telemetry as JSON over HTTP, so point the endpoint at the collector's OTLP/HTTP port, 4318 by default, not at its gRPC one. It also reads these OpenTelemetry variables, and no others (`OTEL_EXPORTER_OTLP_PROTOCOL` included):

- `OTEL_EXPORTER_OTLP_HEADERS`, `OTEL_EXPORTER_OTLP_COMPRESSION` and `OTEL_EXPORTER_OTLP_TIMEOUT`, and the per-signal forms of these and of the endpoint, such as `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT`
- `OTEL_RESOURCE_ATTRIBUTES` and `OTEL_SERVICE_VERSION`
- `OTEL_SDK_DISABLED`
- the batching settings, `OTEL_BSP_*` for traces and `OTEL_BLRP_*` for logs
- `OTEL_METRIC_EXPORT_INTERVAL`, `OTEL_METRIC_EXPORT_TIMEOUT` and `OTEL_EXPORTER_OTLP_METRICS_TEMPORALITY_PREFERENCE`

## Tools [#tools]

`bun nx run peal-server:media-cors` puts the upload CORS rule on the bucket. It reads the media store's `PEAL_S3_*` variables, `PUBLIC_URL` and `TRUSTED_ORIGINS`, with the same defaults as the server. `bun nx run peal-server:bluesky-key` reads nothing.

`bun packages/peal-server/scripts/ads-trial.ts` sends the ads adapter's requests to Meta from your machine, and prints each one with Meta's whole answer. Run it with Bun from the repository root, never through Nx, because Nx keeps a copy of every task's terminal output in its cache.

It reads these from the environment only, so export them from your keychain rather than typing them on the command line:

- `META_APP_ID` and `META_APP_SECRET`
- `PEAL_ADS_TRIAL_TOKEN`, a user token from the Marketing API Tools page of the app dashboard, trimmed and never printed
- `PEAL_ADS_TRIAL_ACTIVATE`, which guards the `activate` step

Everything the script makes is paused and named `peal-trial-…`, and it pauses and deletes only what bears that name. Its `activate` step runs only on an object of the trial's, in the ad account given as `--sandbox-account`, and only when `PEAL_ADS_TRIAL_ACTIVATE` holds today's date in UTC (`YYYY-MM-DD`). The script appends what it sent and received, with credentials masked, to `.local/ads-trial.log` at the repository root, readable by you alone.
